# 59. Импорт мероприятия по ссылке на страницу организатора

Статус: черновик 01.11.2026, ждёт ответов владельца (§10). Основание: решение Р-9
документа 51 (§4.6): организатор вставляет ссылку на СВОЮ страницу мероприятия, платформа
готовит черновик, организатор его подтверждает.

## 1. Что получает организатор

1. В мастере мероприятия есть кнопка «Заполнить по ссылке» рядом с «Заполнить по афише».
2. Организатор вставляет адрес своей страницы.
3. Платформа читает страницу и показывает, что нашла: название, даты, площадку, город,
   описание, картинку, категории с ценами.
4. Каждое найденное значение — **подсказка**, а не готовый ответ. Как с афишей: на вопросе
   мастера появляется кнопка «Со страницы: …». Значение попадает в черновик только после
   нажатия.
5. Мероприятие создаётся обычным путём мастера: event-bundle, черновик, без продаж.

Мы не читаем страницы чужих билетных площадок (Ticketmaster, Eventbrite и подобные). Их
условия запрещают автоматический сбор данных (§6).

## 2. Откуда берутся данные (по приоритету)

| Шаг | Источник | Что берём |
|---|---|---|
| 1 | schema.org `Event` в JSON-LD (`<script type="application/ld+json">`) | всё, см. §3 |
| 2 | Open Graph и обычные мета-теги | `og:title`, `og:description`, `og:image`, `<title>`, `meta description` |
| 3 | Чтение текста страницы моделью (как афиша, `posterread`) | только то, чего не дали шаги 1 и 2 (§4) |

Правила:

1. Значение из шага 1 сильнее значения из шага 2. Шаг 2 только заполняет пустые поля.
2. Модель (шаг 3) вызывается, только когда после шагов 1 и 2 нет даты ИЛИ нет ни одной
   цены. Страница с полным JSON-LD модель не тратит.
3. У каждого поля в ответе есть источник (`json_ld`, `open_graph`, `model`). Экран
   показывает источник модели отдельно: «прочитано ИИ, проверьте».
4. Браузер без JavaScript: мы читаем только HTML, который отдаёт сервер. Страница,
   которая рисует всё скриптом, даст мало данных. Тогда экран предлагает афишу или ручной
   ввод. Безголовый браузер мы не запускаем.

## 3. Разбор JSON-LD

1. Читаем все блоки `application/ld+json`. Принимаем объект, массив и `@graph`.
2. Тип — `Event` и его подтипы schema.org: `MusicEvent`, `TheaterEvent`, `ComedyEvent`,
   `DanceEvent`, `Festival`, `ChildrensEvent`, `EducationEvent`, `ExhibitionEvent`,
   `ScreeningEvent`, `SocialEvent`, `SportsEvent`, `LiteraryEvent`, `BusinessEvent`,
   `VisualArtsEvent`, `FoodEvent`. `EventSeries` с `subEvent` раскрываем в даты.
3. Несколько `Event` на странице: одно название (самое частое), список дат. Дат больше 10 —
   берём 10 ближайших будущих и пишем об этом.
4. Поля:

| JSON-LD | Подсказка | Правило |
|---|---|---|
| `name` | название | до 200 символов, без HTML |
| `startDate` | дата и время сеанса | см. §5 |
| `endDate` | — | не используем (конец сеанса мастер не спрашивает) |
| `doorTime` | «вход с» | только время того же дня |
| `location.name` | площадка | `Place`; `VirtualLocation` → предупреждение «онлайн» |
| `location.address.addressLocality` | город | |
| `location.address.addressCountry` | страна | ISO-код или название; для кнопки страны |
| `location.address.streetAddress` | адрес новой площадки | только если площадку создают |
| `description` | описание | в ART через `richtext.FromLegacy`, до 4000 видимых символов |
| `image` | картинка-кандидат в афишу | строка, массив или `ImageObject`; §7 |
| `offers` | категории | `Offer` → категория `name`/`category`, `price`, `priceCurrency` |
| `offers` (`AggregateOffer`) | категории | из вложенных `offers`; одни `lowPrice`/`highPrice` — только заметка «цены от … до …», категорий не создаём |
| `typicalAgeRange` | возраст | `"18-"` → `18+`; только значения платформы (0+, 6+, 12+, 16+, 18+) |
| `eventStatus` | — | `EventCancelled` и `EventPostponed` → дату не предлагаем, пишем почему |

5. Цена — строка или число. Переводим в минорные единицы по экспоненте валюты, без
   `float` (`"25,00"`, `"25.5"`, `25`). Цена 0 — бесплатная категория. Непонятная цена —
   категория без цены.
6. Валюта — только ISO 4217 из `priceCurrency`. Без неё категория идёт без валюты, мастер
   спросит.

## 4. Чтение страницы моделью

1. Берём видимый текст страницы: без `script`, `style`, `nav`, `footer`. Не больше 20 000
   символов.
2. Модель — текстовая, дешёвая (по образцу `textformat`: `TEXT_FORMAT_LLM_MODEL`, ключ
   `POSTER_LLM_API_KEY`). Инструмент с той же схемой, что у `posterread.Facts`, плюс список дат.
3. Текст страницы — чужие данные. Модель только заполняет схему. Никаких действий, ссылок и
   вызовов по её ответу. Ответ проверяется тем же разбором, что JSON-LD (даты, цены,
   возраст).
4. Лимит — отдельный от афиш: `EVENT_PAGE_READS_PER_ORG_PER_DAY` (предлагаю 30). Считается
   только вызов модели, разбор JSON-LD бесплатен и не считается.
5. Без ключа модели шаг 3 молча пропускается: работают шаги 1 и 2.

## 5. Язык и часовой пояс

1. Тексты берём как написаны на странице. Не переводим. Язык страницы (`inLanguage`,
   `<html lang>`) показываем в ответе, на черновик он не влияет.
2. `startDate` с часовым смещением (`2026-11-20T19:00:00+01:00`): подсказка — дата и время
   **как написаны** (20.11, 19:00). Это время площадки почти всегда.
3. Когда площадка выбрана, мастер сверяет смещение страницы с поясом площадки на этот
   момент. Не совпало — одно предупреждение: «на странице 19:00 по UTC+1, площадка в UTC+2,
   проверьте время». Время мы сами не пересчитываем.
4. `startDate` без смещения — дата и время как есть, без проверки.
5. Только дата без времени — подсказка даты, время мастер спросит.
6. Прошедшие даты не предлагаем.

## 6. Чужие билетные площадки

1. Список доменов известных площадок хранится в коде (`ticketmaster.*`, `eventbrite.*`,
   `livenation.*`, `dice.fm`, `fever*`, `entradas.com`, `seetickets.*`, `ticketswap.*`,
   `eventim.*`, `goout.net`, `ticketportal.*`, `bil24.*` и другие).
2. Адрес из списка (и адрес, куда ведёт переадресация) — отказ 422
   `event_page.ticketing_platform` до чтения тела. Текст: «Это страница билетной площадки.
   Вставьте ссылку на страницу мероприятия на вашем сайте».
3. Свою страницу на `tickets.arenasoldout.com` не читаем: для повтора есть «Повторить как
   новое».
4. Право на страницу мы не проверяем. Экран говорит «ссылка на страницу на вашем сайте».

## 7. Картинка

1. Кандидат: `image` из JSON-LD, иначе `og:image`.
2. Платформа скачивает её тем же защищённым клиентом (§8): JPEG или PNG, до 16 МБ (как
   side-load афиши в импорте), проверка по первым байтам, а не по заголовку.
3. Картинка сохраняется как объект media организации, `owner_type = event_poster`, ни к
   чему не привязана. В ответе — `media_id`, ширина, высота.
4. Мастер предлагает её на вопросе об афише: «Взять картинку со страницы». Узкая (меньше
   1000 px) — предлагаем с предупреждением, как сейчас для фото.
5. Картинку модель не читает (афишу организатор может прислать сам).

## 8. Защита исходящего запроса

Всё через `internal/platform/egress`, политика `egress.Fetch` (PR #223):

1. Только `http` и `https`. Без логина в адресе, без `#`-части (`CheckURL`).
2. Адрес проверяется при подключении: loopback, частные сети, link-local, метаданные облака
   отклоняются на уровне сокета. Это же правило для каждой переадресации (до 5).
3. Таймаут всего запроса — 10 секунд. Тело HTML — не больше 2 МБ (`io.LimitReader`), больше
   — 422 `event_page.too_large`.
4. `Content-Type` — `text/html` или `application/xhtml+xml`. Иначе 422 `event_page.not_html`.
5. Кодировка — из заголовка и `<meta charset>` (`golang.org/x/net/html/charset`).
6. Свой `User-Agent`: `ArenaSoldOutBot/1.0 (+https://arenasoldout.com/bot)`. Cookies не
   храним, JavaScript не выполняем.
7. В логи и ошибки — только origin (`egress.Origin`), не полный адрес и не текст страницы.
8. Частота: 20 чтений страниц в час на организацию (в памяти процесса, как
   `ratelimit.SlidingWindow`).

## 9. API и клиенты

### 9.1 Маршрут

`POST /v1/organizations/{org_id}/event-page-facts`, право `event.update` (владелец и
менеджер, как чтение афиши). Тело: `{"url": "https://…"}`. Ничего не создаёт, кроме объекта
media картинки (§7).

Ответ 200:

```json
{
  "facts": {
    "name": "…", "age": "16+", "description": "…",
    "venue_name": "…", "city": "…", "country": "ES", "street": "…",
    "dates": [{"date": "2026-11-20", "time": "19:00", "doors": "18:30", "utc_offset": "+01:00"}],
    "categories": [{"name": "Партер", "price_minor": 2500, "currency": "EUR"}],
    "image": {"media_id": "…", "width": 1200, "height": 1500}
  },
  "sources": {"name": "json_ld", "dates": "json_ld", "categories": "model"},
  "final_url": "https://…",
  "language": "es",
  "warnings": [{"code": "event_page.some_dates_skipped", "count": 3}]
}
```

Ошибки: 400 `event_page.invalid_url`; 422 `event_page.destination_not_allowed`,
`event_page.ticketing_platform`, `event_page.not_html`, `event_page.too_large`,
`event_page.nothing_found`; 503 `event_page.fetch_failed` (сайт не ответил, таймаут, 4xx/5xx
сайта — код сайта в `details.status`); 429 `event_page.rate_limited`. Не 502: Cloudflare
подменяет тело.

### 9.2 Бот

1. Первый вопрос мастера: кнопка «Заполнить по ссылке» рядом с «Заполнить по афише».
   Шаг `stEvLinkAsk` ждёт адрес.
2. Если на вопрос о названии прислали адрес — бот спрашивает «Прочитать эту страницу?».
3. Пока читается — «Читаю страницу…» (после 1,5 секунды, как с афишей).
4. Ответ кладётся в `Draft.Hints` (тот же механизм `wizard_hints.go`). Расширения: список
   дат (подсказка для даты номер N), страна, «вход с», картинка.
5. После чтения — одно сообщение «Что нашли на странице» (как `hintsNote`), дальше обычные
   вопросы с кнопками «Со страницы: …».
6. Тексты `bot.wz.link_*` на всех языках бота (en, ru, es).

### 9.3 Веб-ивент-центр

1. В мастере рядом с афишей — поле «Ссылка на страницу мероприятия» и кнопка «Прочитать».
2. Ответ идёт в тот же обзор, что у афиши (`posterHints.ts` → `buildPlan`): пустые поля
   предлагаются, заполненные — замена выключена по умолчанию.
3. Отличия от афиши: дат может быть несколько — предлагаются для 1-й, 2-й… даты; картинка
   предлагается как афиша.
4. Тексты в `src/lib/i18n/{en,ru,es}.ts`, коды ошибок — в `API_ERROR_STEMS`.

### 9.4 Страница без дат или цен

1. Нет дат — черновик без дат. Мастер спрашивает дату как обычно. Сообщение: «На странице
   нет даты, укажите её».
2. Нет цен — категории не предлагаем. Мастер спрашивает билеты как обычно.
3. Ничего не нашли (ни названия, ни даты) — 422 `event_page.nothing_found`. Экран
   предлагает афишу или ручной ввод.
