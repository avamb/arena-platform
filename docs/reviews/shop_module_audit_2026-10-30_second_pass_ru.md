### Побочный эффект SA-09: `paid_at` у любого `manual_review`

`SetShopOrderStatus` ставит `paid_at` для `paid` и `manual_review`. Потребители `shop_orders.paid_at` сегодня:
окно скачиваний (не затрагивается: скачивание разрешено только для `paid`, `shipped`, `partially_refunded`),
публичный ответ статуса заказа, карточка заказа в ивент-центре (строка «Оплачен» в хронологии, `orderTimeline`).
Денежных отчётов и биллинга по `shop_orders.paid_at` нет (`billing_collect` читает только `orders`), возвраты на `paid_at`
не смотрят (требуют `succeeded` у платежа). Значит, сломанных расчётов нет, но заказ с неподтверждённым платежом
выглядит оплаченным для покупателя и менеджера — это SB-02.

## Новые находки

### SB-01. Заказ с неподтверждённым платежом можно отправить, товар уходит без денег — высокая, исправлено

- **Где:** `apps/backend/internal/platform/shop/orders.go`, `Ship`, ветка `case StatusManualReview`.
- **Что не так:** после SA-09 заказ, чей платёж AllPay отдал в `manual_review` (сумма не совпала, AllPay сообщил
  о возврате до подтверждения, списание в другой валюте), паркуется в `manual_review`. Ветка `Ship` для `manual_review`
  писалась для «поздней оплаты без товара» (деньги есть) и проверяла только остаток. Платёж не проверялся: менеджер
  нажимает «Отправлен», товар списывается, письмо «отправлен» уходит, а денег может не быть. Telegram (SB-02) прямо
  пишет «Оплачено», что подталкивает к отправке.
- **Воспроизведение:** `TestShopSecondPass_PaymentReviewOrderShipsOnlyAfterThePaymentSucceeded` на коде до исправления:
  ship отвечает 200, заказ `shipped`, остаток 3 → 2 при платеже `manual_review`.
- **Исправление (сделано):** для заказа с `metadata.review_reason = payment_manual_review` отправка требует платёж
  `succeeded`, иначе 409 `shop.payment_unconfirmed`; парковка по нехватке товара (`stock_short`) работает как раньше.
  Код описан в openapi (TS-клиент перегенерирован), в ивент-центре сопоставлен со стемом `shopNotShippable`,
  правило записано в `AGENTS.md`.

### SB-02. Заказ с неподтверждённым платежом везде показан оплаченным — средняя

- **Где:** `shop/validate.go:221` (`PublicStatus`: `manual_review` → `paid`), `adapters/postgres/gen/shop_orders.sql.go:408`
  (`paid_at` для `manual_review`), `apps/event-center/src/lib/shop.ts:653` (строка «Оплачен» по `paid_at`),
  `salesnotify/shop.go:181-191` и `i18n/locales/*.toml` `salesnotify.shop.review_paid` / `review_body`.
- **Что не так:** для парковки по платежу (SA-09) покупатель на странице заказа видит «Оплачено», корзина очищается;
  менеджер видит в хронологии «Оплачен»; группа логиста получает «💰 Оплачено: 95 ₪» и текст «Оплата пришла, когда бронь
  уже закончилась, а товара не осталось» — обе части неверны: деньги не подтверждены, товар был.
- **Воспроизведение:** `MarkPaymentReviewTx` на ожидающем заказе (как в `TestShopAudit_PaymentManualReviewParksTheOrder`),
  затем `GET /v1/public/shop/checkout/{token}` → `status: paid`, `paid_at` заполнен; событие `v1.shop.order.manual_review`
  форматируется `FormatShopOrderReview` с текстом про оплату.
- **Исправление:** отдельный запрос парковки без `paid_at`; `PublicStatus` для `payment_manual_review` — `pending`
  (или новый `review` с текстом «проверяем платёж»); в Telegram ветка по `review_reason` с новыми ключами во всех пяти
  каталогах (`TestShopTexts_EveryLocaleHasEveryKey`).

### SB-03. Потолок неоплаченных заказов на адрес зависит от `TRUSTED_PROXY_COUNT` — высокая (эксплуатация)

- **Где:** `hshop/handler.go:264-284` (`clientIP` → `httputil.TrustedClientIP(r, TrustedProxies)`), `shop/checkout.go:308-319`
  (`MaxPendingPerClient = 3`), `mount_shop.go:111`.
- **Что не так:** ключ клиента — адрес, который API считает адресом покупателя. За Cloudflare и Traefik при неверном
  `TRUSTED_PROXY_COUNT` это адрес узла Cloudflare или Traefik. Все покупатели этого узла делят три неоплаченных заказа
  на магазин: четвёртый человек, открывший оплату, получает 409 `shop.too_many_pending`, пока кто-то не оплатит или
  не истечёт резерв (около 33 минут). `AGENTS.md` фиксирует, что API стенда видит адрес Cloudflare при `TRUSTED_PROXY_COUNT=1`.
  В чек-листе выпуска пункта не было.
- **Исправление:** пункт добавлен в чек-лист (проверка двумя оформлениями из разных сетей и запросом по `buyer_ip_hash`).
  Перед выпуском проверить значение на проде. Надёжнее брать `CF-Connecting-IP` для маршрутов магазина, когда запрос
  пришёл с адреса Cloudflare (отдельная доработка).

### SB-04. Из парковки по платежу нет пути в «оплачен», цифровой заказ не выдать — средняя

- **Где:** `shop/payment.go:39-41` (`FulfillPaidOrderTx` выходит для любого `manual_review`),
  `hcheckout/payment_intents.go:507` (`HandleTransitionPaymentIntent` не вызывает `applyShopPayment`),
  `shop/checkout.go:548-552` (скачивание только для `paid`/`shipped`/`partially_refunded`).
- **Что не так:** когда оператор решает, что платёж прошёл (переход `manual_review → succeeded` через
  `POST /v1/payment-intents/{id}/transition` или повторный вебхук), заказ магазина остаётся `manual_review`: письма
  «заказ получен» нет, события `v1.shop.order.paid` нет. Физический заказ теперь можно отправить (SB-01 проверяет
  `succeeded`). Цифровой — нельзя: отправка 409 `order_not_shippable`, скачивание закрыто. Покупателю, который
  заплатил, остаётся только возврат.
- **Исправление:** в `FulfillPaidOrderTx` считать заказ с `payment_manual_review` ожидающим (перепроверка остатка,
  затем `markPaidTx` или парковка `stock_short`) и вызывать ту же проекцию из маршрута перехода платежа.

### SB-05. Лимит 20 скачиваний расходуется просмотрами страницы заказа — средняя

- **Где:** `hshop/public.go:387-445` (`HandlePublicCheckoutDownloads` подписывает и списывает по одной ссылке на строку
  при каждом вызове), `apps/shop-page/src/main.ts:365-421` (вызов на каждом открытии страницы оплаченного заказа и
  на кнопке «Обновить ссылки»), письмо магазина ведёт на эту страницу.
- **Что не так:** «скачивание» считается выдачей списка ссылок, а не загрузкой файла. Покупатель, открывший письмо
  и страницу заказа 20 раз (или 20 раз нажавший «Обновить ссылки», ссылки живут 15 минут), получает 410
  `shop.download_expired`, не скачав файл ни разу.
