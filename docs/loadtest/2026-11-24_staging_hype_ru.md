# Нагрузочный «хайп» на стенде: открытие продаж зала с местами — 24.11.2026

Скрипт: `ops/loadtest/staging-hype.mjs`, живой вид: `ops/loadtest/live-view.mjs`. Время — по Мадриду.
Подробный отчёт с идентификаторами стенда и разбором найденных ошибок хранится в приватных заметках владельца (репозиторий публичный).

## Что делали

Стенд, тестовая организация, зал с местами на 767 мест, Stripe в тестовом режиме, встроенная форма оплаты, предзаказ при открытии окна заказа (`preload-payment="checkout"`).

- Покупатели повторяют запросы виджета: мероприятие, схема зала, состояние мест, опрос изменений каждые 3 с, выбор 1–4 мест рядом в одном ряду, `checkout/start` (быстрый путь `prepare:true` + `/buyer` или обычный), оплата.
- Оплата — подписанный вебхук `checkout.session.completed` (сессию `ui_mode=elements` нельзя подтвердить с сервера, только в браузере); несколько настоящих браузеров (Playwright, 375 px) платят тестовой картой.
- На время больших прогонов воркеру `EMAIL_MODE=log` (письма не отправляются) и поднятый лимит по адресу у API, после — вернули как было.

## Результаты

| | 900 покупателей за 1 мин | 2000 за 5 мин | 5000 за 5 мин (3 процесса) |
|---|---|---|---|
| Зал в брони или продан | 60 с | ~60 с | ~30 с |
| Продано | 767 / 767 | 767 / 767 | 740 / 767 (+27 в свежих бронях) |
| Двойные продажи (`audit.sql`) | 0 | 0 | 0 |
| Зависшие брони | 0 | 0 | 0 |
| 5xx и 429 стенда | 0 | 0 | ошибки только в 30 с перезапуска api и на найденной ошибке (см. ниже) |
| `checkout/start` p50 / p95 | 0,24 / 0,57 с | 0,41 / 3,8 с | 1,3 / 2,1 с |
| Страница мероприятия p95 | 0,43 с | 1,75 с | 5,1 с |
| Состояние мест (изменения) p95 | 0,25 с | 0,56 с | 0,13 с |
| От вебхука до «оплачено, есть билеты» p95 | 2,2 с | 3,2 с | 3,5 с |

Поведение покупателей в больших прогонах: сразу платят 55 %, медленно (2–25 мин) 10 %, бросают с отменой 15 %, молча 10 %, отказ карты и повтор 5 %, двойное нажатие / перезагрузка / две вкладки 5 %; покупатели без билетов ждут вернувшиеся места.

- Неоплаченная бронь держит места 33 минуты (сессия Stripe живёт не меньше 30 минут). Молча брошенные места вернулись ровно через 33 минуты и были раскуплены ожидающими за 3–6 с. Скорость продажи всего зала задаёт срок брони, а не сервер.
- Поздние оплаты после конца окна отклонены, билетов на чужие места не выпущено. Повторные и запоздалые вебхуки (`completed` ещё раз, новый номер события, `expired` после оплаты) ничего не сломали. Двойное нажатие, перезагрузка и две вкладки лишних заказов не дали.
- «Место уже занято»: на обычном пути оно приходит после заполнения формы при «Оплатить» (368 из 375 дошедших до оформления), на быстром — при открытии окна заказа, до e-mail. Для ажиотажа быстрый путь лучше для покупателя.
- Отмена распроданного сеанса из бота: журнал изменения записан, задания писем выполнены (при `EMAIL_MODE=log` — пропущены), заказы, билеты и места не тронуты (массового возврата после отмены нет).

## Что нашли (задачи)

1. Ошибка в оплате при определённой последовательности действий покупателя — исправляется отдельной задачей; подробности в приватных заметках до выката исправления.
2. Перезапуск api во время продаж даёт ~30 с ошибок (одна копия api за Traefik); без перерыва — только две копии и поочерёдный перезапуск.
3. Страница мероприятия — самый медленный запрос под пиком (p95 5,1 с на 5000): кандидат на кэш или облегчённый ответ.
4. Отменённый сеанс нельзя повторить на другую дату (`docs/known-issues.md`).
5. Настройка доверенных прокси и лимит по адресу за Cloudflare надо проверить (`docs/known-issues.md`).
