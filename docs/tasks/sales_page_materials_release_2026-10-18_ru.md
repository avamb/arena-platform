# Материалы страницы продаж — проверка и подготовка выпуска

Дата: 18.10.2026. Ветка `codex/sales-page-materials`, база `820393174209cba99da6c76e541435c25f07f662`.

## Что выпускается

В Event Center на карточке мероприятия — редакторы галереи (6), видео (4), других продавцов (3), адреса площадки, точки на карте и фотоотчёта (30). Данные сохраняются в существующем API. Tickets-page и внешний виджет отображают сохранённые материалы. Реальные адреса площадок с датами добавлены в публичные ответы; адрес продавца не подменяет место проведения. На странице продаж нет двойного блока от виджета.

Использованы исходные реализации PR #164 и #181, адаптированные к текущему master, без слияния их старых веток. Старые PR не закрывались. Изменений миграций и платёжной логики нет.

## Независимая проверка и исправления

- Исправлена очистка адреса: редактор синхронизирует legacy address и структурированные строки, поэтому старый адрес не возвращается после удаления.
- При отказе сохранения карты введённые координаты остаются в форме; ошибка не выглядит как успех.
- Права в live-тесте проверяются по фиксированным ожиданиям: owner/manager редактируют, agent только читает; прямой запрещённый запрос даёт 403.
- Для воспроизводимого теста с локальным HTTP API img-src разрешает конкретный настроенный API origin. Общего разрешения http: нет; production origin остаётся HTTPS. Script/frame sandbox не ослаблен.
- Детерминированные зависимости tickets-page/widget переустановлены через npm ci из lockfile. Production Docker build также использует npm ci.
- Добавлен исходный SQL для нового hand-maintained wrapper адресов площадок.

## Внешние плееры: предел доказательства

С действующими sandbox/CSP YouTube и Vimeo embed-документы реально ответили HTTP 200. Vimeo показал элементы управления плеером. Это не доказательство воспроизведения звука/видео до конца; фактическое воспроизведение не подтверждено. Rutube проверен на уровне allowlist/URL/CSP и UI, реального воспроизведения не проверено. Во всех случаях покупателю остаётся ссылка на оригинал. Доступность конкретного ролика, право на embed и региональные ограничения контролирует провайдер.

## Порядок выпуска и откат

После успешного CI и разрешения владельца: API → tickets-page со встроенным новым widget → Event Center. Внешний widget публиковать по принятому отдельному процессу версий; не менять сторонние сайты автоматически. До API старые поля остаются совместимыми, новый frontend переносит отсутствие venues/materials.

Перед обновлением сохранить точные текущие image digest/APP_COMMIT для каждого изменяемого сервиса и конфигурацию в защищённом backup, не в Git. Миграций нет: откат — прежние образы API/страницы/Event Center; уже сохранённые материалы остаются в прежних таблицах и не удаляются.

Production smoke: страницы с материалами и без, выбор даты/билета, галерея, партнёрская ссылка, адрес/карта, редактор с сохранением только на контрольном мероприятии, read-only роль, HTTP/CSP, health/restarts/errors. Не проводить реальные платежи и не отправлять письма для этого выпуска.
