Дата: 2026-10-28. Оркестратор: Claude в сессии владельца. Исполнители: подагенты
(модель по сложности), каждый в своём worktree и своей ветке, результат PR в

Контекст: решения Анны (`einatwinery_call_anna_2026-10-26_ru.md`), разбор
Shopify (`einatwinery_shopify_exit_options_2026-10-22_ru.md`), исследование

## 0. Рамка

- Модуль «товары организатора» (мерч), первый клиент Einat Winery / Vino&Co.
  Arena только SaaS: деньги берёт организатор через свой аккаунт PayPlus.
- Этап 1: дизайн витрины один в один с нынешним Shopify (тема Dawn, русский,
  заглушка 18+, баннер скидки, меню, страницы). Никакого редизайна.
- База для разработки: текущий `master` (эта сессия сидит на устаревшей ветке
  `feat/ec-01-bot-dialogs`, голова миграций там 0130, на проде уже за 168).
  Каждый агент начинает с `git fetch` и ветки от `origin/master`.
- **Срок владельца: всё до 5 ноября 2026 (8 дней).** Поэтому объём первой
  версии урезан до того, что можно принять и переключить за неделю (§7), всё
  остальное идёт второй волной после переключения.

## 2. Пакеты работ

Обозначения: модель, зависимости, что считается готовым. Ветки `feat/shop-<код>`.

### S0. Спецификация модуля (opus, 1–2 дня, блокирует всё остальное)

Файл `08_architecture/47_merch_shop_module_ru.md` (46 занят). Содержание:
- Таблицы: `shop_products` (org, slug, name, description, status, media),
  `shop_variants` (sku, price_minor, currency, stock, unit limits),
  `shop_orders` (org, channel, customer, buyer, address, delivery kind
  shipping/pickup, pickup session, status, money, payment_intent),
  `shop_order_items`, `shop_stock_moves` (резерв с TTL, списание, возврат),
  `shop_settings` на уровне организации (плоская доставка, валюта, 18+,
  страны). Общие сущности: `customers`, `payment_intents`, `refunds`,
  `promo_codes`, outbox-события `v1.shop.order.paid|shipped|refunded`.
- Маршруты: организация (`/v1/organizations/{org}/shop/...` CRUD товаров,
  заказы, выполнение, возврат), публичные (`/v1/public/shop/{org_slug}` каталог,
  `checkout/start`, `checkout/{token}` статус, `payment-return`), host-роутинг
  витрины по домену организатора.
- Оплата через существующую абстракцию `PaymentStarter` (Stripe, Flitt,
  PayPlus), вебхук по config_id, политика return URL.
- Экраны ивент-центра и карточки бота, письма, Telegram-подписка с фильтром.
- Нумерация миграций от головы master, OpenAPI, бэклог SHOP-01…NN с размером и
  моделью. Готово: ревью оркестратора, замечания закрыты.

### L1. Бэкенд-ядро (opus; после S0)

SHOP-01 миграции + sqlc-запросы; SHOP-02 агрегат и сервис (цены в минорных
единицах, резерв остатка с TTL по образцу брони, sweep); SHOP-03 API
организации; SHOP-04 публичный каталог и checkout/start → PaymentStarter,
статус по токену; SHOP-05 выполнение заказа (new → packed → shipped/picked_up),
возврат через `refunds`; интеграционные тесты на скретч-базе. Готово: тесты
зелёные, OpenAPI и TS-клиент перегенерированы, PR.

### L2. Провайдер PayPlus (opus; независим от L1, можно сразу после S0)

SHOP-10 `internal/adapters/payplus`: generateLink, View, RefundByTransactionUID,
VerifyCredentials, `PAYPLUS_API_BASE_URL` seam (запрещён в production);
SHOP-11 подключение в `hcheckout` как третьего hosted-провайдера: колбэк на
`/v1/public/payment-webhook/{config_id}` с проверкой `hash` (base64
HMAC-SHA256 по сырым байтам), `more_info` = checkout_session_id, дедуп по
`transaction.uid`, статус `000`; SHOP-12 заглушка PayPlus для тестов по образцу
`stripe-stub.cjs` + интеграционные тесты на БИЛЕТНОМ чекауте (доказательство
независимо от магазина). Готово: билет куплен и возвращён через заглушку, PR.

### L3. Витрина (sonnet + навык frontend-design; после S0, API по контракту)

Новое приложение `apps/shop-page` (Vite + TS, как `tickets-page`), данные через
публичный API по OpenAPI из S0, до готовности L1 на мок-сервере.
SHOP-20 снятие дизайна: из экспорта темы Dawn (settings_data.json: цвета,
шрифты, радиусы) и с живого сайта (HTML/CSS секций) воспроизвести один в один:
шапка с меню и иконками, баннер скидки, заглушка 18+, главная с сеткой
товаров, карточка товара, коллекция, корзина-ящик, подвал с меню «Наши
правила» и «Информация для Вас», страницы О нас / Партнёры / Контакты /
политики. Шрифты через Google Fonts (эквивалент шрифтов Shopify).
SHOP-21 оформление заказа: покупатель, адрес, выбор доставка 50 ₪ / самовывоз
на мероприятии, промокод, согласие 18+, переход на страницу PayPlus, страница
статуса и возврата с оплаты. SHOP-22 мобильная версия (92 % трафика),
Lighthouse, SEO-теги и sitemap, 301-таблица старых адресов. SHOP-23 Meta pixel
(Purchase с суммой). Готово: пиксельное сравнение с Shopify на десктопе и
телефоне, владелец принял на стенде.

### L4. Ивент-центр и бот (sonnet; после L1 API)

SHOP-30 веб-ивент-центр: товары (список, карточка, фото, цена, остаток, статус),
заказы магазина (список, карточка, статусы выполнения, возврат, «копировать
для курьера» построчно в порядке полей Анны); SHOP-31 бот: карточка товара
(создать/изменить остаток и цену), карточка заказа с кнопками «собран»,
«отправлен», «выдан»; SHOP-32 права: `shop.read/manage` у owner и organizer
(миграция, парити суперадмина). Готово: e2e бота и smoke-тесты веб-центра.

### L5. Уведомления и письма (sonnet; после L1 событий)

SHOP-40 `sales_notification_subscriptions`: поле «что присылать» (билеты /
товары / всё), отдельная группа логиста получает только `shop.order.paid` с
реквизитами доставки в порядке полей Анны; SHOP-41 письма покупателю «заказ
принят» и «отправлен / готов к выдаче» (ru, he, en) в дизайне заказного письма;
SHOP-42 ops-watchdog: оплачен, но не собран более N дней. Готово: тесты
шаблонов, живой прогон в тестовую группу.

### L6. Перенос данных (sonnet; после L1 схемы)

SHOP-50 `cmd/arena-shop-import`: товары из Products CSV (варианты, цены, фото
side-load по URL в `media_objects`), покупатели из Customers CSV в
`customers` с согласиями на рассылку, промокоды; SHOP-51 история заказов из
Orders CSV как `shop_orders` с источником `shopify` (для статистики и повторных
продаж, без платежей); SHOP-52 отчёт сверки: число товаров, покупателей,
заказов, сумм до/после. Готово: прогон на стенде, сверка сходится.

### L7. Домен, хостинг, переключение (sonnet, ops; после L3)

SHOP-60 домен организатора для витрины: таблица/настройка `custom_domain` у
организации, роутинг по Host в shop-page, Traefik-правило и Let's Encrypt,
Cloudflare; SHOP-61 301-редиректы с адресов Shopify (`/products/<handle>`,
`/collections/*`, `/pages/*`), robots и sitemap; SHOP-62 чеклист переключения:
DNS, проверка оплаты боевыми ключами на 1 ₪ с возвратом, пауза Shopify,
мониторинг первые сутки. Готово: домен отвечает нашей витриной, старые ссылки
ведут на новые страницы.

## 4. Правила для каждого агента (в бриф)

- Ветка от `origin/master`, worktree; перед запуском агентов включить
  `skip-worktree` на AGENTS.md и короткий CLAUDE.md (580 КБ валят агентов, см.
  память 28.10).
- Миграции: номер от головы master, пин головы в тестах, грант новых прав
  `platform_superadmin` в той же миграции.
- Любое изменение API: openapi.yaml, `gen-openapi`, `gen-ts-client` в одном PR.
- Деньги в минорных единицах, best-effort записи под SAVEPOINT, пул не трогать
  внутри транзакции.
- Интеграционные тесты за тегом `integration` на скретч-базе, не на общем стенде.
- Коммит и push после каждого шага, PR с описанием, что проверено руками.
- Отчёт агента: что сделано, что не удалось, какие решения нужны.

## 5. Роль оркестратора

Пишу брифы, запускаю агентов по порядку выше, ревью каждого PR (opus на ревью
бэкенда), слежу за конфликтами по файлам, собираю стенд, веду этот документ и
память. Владельцу приношу только решения и результаты для приёмки.

## 6. Риски

- Ключи PayPlus и тестовый контур могут задержаться: L2 стартует на заглушке по
  документации, но приёмка только на `restapidev`.
- Пиксельное совпадение с Dawn требует экспорта темы; без него снимаем с живого
  сайта, но шрифты и мелкие отступы могут отличаться.
- Сезон: если к 1 декабря витрина не принята, Shopify остаётся на помесячной
  оплате ещё месяц, переключение после сезона.
