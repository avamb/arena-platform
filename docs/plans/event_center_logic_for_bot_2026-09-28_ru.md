## 1. Кто что хранит

- **Arena — источник истины для продаж**: ивент (action), сеансы (action event / session),
  категории (tier) с ценами, количеством, окнами продаж, графиком цены и цепочкой; площадки,
  города, промоутеры организации.
- **Сайт WordPress**:
  - на **каждый сеанс свой товар WooCommerce** (скрытый у Lampyris, он же страница ивента у Vino).
    Товар создаёт мастер **до** отправки сеанса в Arena, его id входит в `externalRef`;
  - у Lampyris дополнительно **страница мероприятия** (`past-event`), связанная с товаром
    (`_lampyris_event_id` на товаре, `bil24_product_id` на странице);
  - материалы (фото, видео, партнёры), письма, тур, промоутер из справочника сайта — мета
    ивента на сайте, в Arena их нет;
  - после сохранения синхронизация каталога (GET_ALL_ACTIONS) подтягивает цены, остатки,
    категории в товар (`bil24_price_matrix_json`).
- **Доступ к Arena** — ключ организации (`Authorization: Bearer ak_…`) в настройке сайта
  `lops_arena` (`base_url`, `org_id`, `api_key`, `organizer_name`, `product_status`,
  `kick_sync`, `site_slug`). Ключ никогда не уходит в браузер, все вызовы — с сервера сайта.
  Ключу нужны права: `import.bil24_session` (пакет ивента), `event.read`, `venue.read`,
  `venue.create`, `city.create`, `promoter.read`, `promoter.manage`, и **привязанный канал
  продаж сайта** (без канала ивент не публикуется в каталог сайта — предупреждение
  `import.channel_publication_skipped`). 28.09 прод-ключам обоих сайтов недоставало четырёх
  прав — добавлены SQL-ом; новые ключи выпускать сразу со всеми.
- **Права оператора на сайте**: `LOPS_CAP_MANAGE_SALES` (менеджер продаж ивент-центра).

## 2. Порядок вопросов мастера (создание)

Принцип владельца: вопросы от простого к сложному, показывать только то, что нужно для
данного ответа (та же цепочка задумывалась для Telegram/WhatsApp-бота). Мастер помнит
последние ответы оператора (страна, город, площадка, возраст, промоутер, валюта) и
начинает с них.

### 2.0 «Кто продаёт билеты» — только Lampyris

Показывается только на сайте, где ивент — отдельная страница мероприятия (Lampyris), и только
при создании (не в «Изменить»).

| Ответ | Что дальше |
|---|---|
| **Продаём мы** (по умолчанию) | полный путь через Arena (разделы 2.1–2.5) |
| **Продают партнёры** | Arena не участвует: блоки «Когда и где» с сеансами и «Билеты» скрыты, вместо них поля страницы (раздел 6) |
| **Пока никто — только анонс** | то же, что «партнёры», но ссылки на продажу не нужны |

### 2.1 Ивент

| Поле | Правило |
|---|---|
| Название | обязательно, до 200 символов. «Укажите название ивента.» |
| Возраст | обязательно, одно из `0+ 6+ 12+ 16+ 18+` (по умолчанию последний выбранный, иначе 18+) |
| Промоутер | список промоутеров организации из Arena; первым пунктом — сама организация (пустое значение = организация). «+ Другой промоутер…» — создать: название (как в билете, обязательно), ИНН/IČO, телефон (необязательно). Дубль имени → «Такой промоутер уже есть — выберите его из списка.» |
| Афиша | файл PNG/JPG до 5 МБ, пропорции 4:5 (1080×1350) или квадрат (допуск ±2 %), ширина ≥ 1080 px. Всё важное — в центральном квадрате (сайт режет верх/низ в карточках). Без афиши карточка ивента на сайте не открывается. В «Изменить» новый файл нужен только для замены |

Промоутер ≠ организация: организация продаёт, промоутер проводит. Промоутер печатается в
билете в строке «Организатор», идёт в выгрузки (`COALESCE(promoter, organizations.name)`),
а юрлицо продавца для MACS остаётся организацией.

Ошибки афиши (дословно): «Афиша должна быть картинкой PNG или JPG.», «Файл афиши больше 5 МБ —
сохраните его с меньшим качеством.», «Афиша W×H — нужен формат 4:5 (1080×1350) или квадрат
(1080×1080).», «Афиша W×H слишком маленькая — нужна ширина не меньше 1080 px.»

### 2.2 Когда и где

Вопрос: **«Один сеанс» / «Несколько»** (несколько — тот же ивент в другие дни или в других
городах).

Каждый сеанс:

| Поле | Правило |
|---|---|
| Дата | обязательна, реальная дата |
| Время начала | обязательно, `ЧЧ:ММ`, по умолчанию 20:00 |
| Страна | из справочника Arena (`GET /v1/geo/countries?lang=ru`); сначала страны, где у организации есть площадки |
| Город | города страны (`GET /v1/geo/cities?lang=ru&country_id=`), в списке только те, где у организации есть площадки, + «+ Другой город…» |
| Площадка | площадки организации в этом городе (`GET /v1/organizations/{org}/venues`) + «+ Новая площадка…» |
| Мест в зале | целое ≥ 1; подставляется из обычной вместимости площадки, пока оператор не ввёл своё. Нужно для «одной категории» и для «по очереди»; для «все сразу» места задаются у каждой категории |

- Часовой пояс сеанса = пояс площадки (из Arena); время вводится местное.
- Два одинаковых сеанса (та же дата, время и площадка) — ошибка.
- «+ сеанс» копирует предыдущий (страна, город, площадка, места), дата очищается.
  **Билеты у всех сеансов одинаковые**; отличия потом — у конкретного сеанса.
- Валюта по умолчанию подставляется по стране площадки (пока оператор не ввёл свою).

**Новая площадка** (диалог): страна → город (или новый город: название; Arena сама вернёт уже
существующий город с таким именем на любом языке или с тем же slug, копию не создаёт) →
часовой пояс (спрашивается, только если в стране их несколько) → название (обязательно) →
адрес → (дополнительно) точка на карте «широта, долгота», обычная вместимость.
Если в этом городе уже есть площадка с таким именем (без учёта регистра) — выбирается она,
новая не создаётся. Площадка после создания доступна всем ивентам организации.
Вызовы: `POST /v1/organizations/{org}/cities` `{country_id, name, locale:"ru"}`,
`POST /v1/organizations/{org}/venues` `{name, city_id, address_line1, country (ISO2), timezone,
status:"active", capacity_default?, geo_lat?, geo_lng?}`.

### 2.3 Билеты

Вопрос: **«Одна категория» / «Несколько»**.

**Одна категория** — все билеты одинаковые, даже если цена со временем растёт.
- Название (по умолчанию «Входной билет»), цена.
- Вопрос «Цена меняется со временем?» — «Нет» / «Да, по датам». При «да» — строки
  «с даты → новая цена» (минимум одна, даты строго по возрастанию). Название на сайте не
  меняется, уже купленные билеты не дорожают.
- Все места зала — у этой категории.

**Несколько** → вопрос «Как продаются категории?»:

1. **Все сразу — покупатель выбирает** (например VIP и Стандарт одновременно). У каждой
   категории: название, цена, **своё число мест**. Минимум две категории.
2. **По очереди — цена растёт ступенями** (например «Старт» → «Для друзей» → «В последний
   момент»). Продаётся одна категория за раз, все делят «Мест в зале». У каждой категории,
   кроме последней, конец ступени:
   - «продаётся до» даты (включительно, до конца дня в поясе площадки), **и/или**
   - «или первые N билетов».
   Категория заканчивается тем, что наступит раньше. Нужно указать хотя бы одно. Даты
   ступеней должны идти по возрастанию. Последняя категория продаётся до начала сеанса.
   Минимум две категории.

Общие правила категорий:
- Цена: число ≥ 0, до 2 знаков после запятой; принимаются «199», «99,90», «1 200».
- Названия категорий не повторяются (без учёта регистра).
- Пустые строки игнорируются.

Сообщения (дословно, для повторного использования в боте): «Укажите название категории,
например «Входной билет».», «Укажите цену билета числом, например 199.», «Добавьте хотя бы
одно повышение цены или ответьте «Нет».», «Для нескольких категорий нужно минимум две. Если
категория одна — выберите «Одна категория».», «Категория «X»: укажите дату, до которой она
продаётся, или число билетов.», «Категории по очереди: «X» должна продаваться дольше
предыдущей.», «Категория «X» указана дважды.»

### 2.4 «Дополнительно» (вкладки, можно не открывать)

Материалы и письма **общие для всех сеансов** ивента.

1. **Фото и видео** — галерея (URL из медиатеки сайта), видео (ссылки), «Где ещё купить» —
   партнёры (название + ссылка). На странице Lampyris показываются первые 6 фото, 4 видео,
   3 партнёра.
2. **Письма**:
   - «Стандартные письма» (по умолчанию) — обычное письмо с билетами, настроенное для всех
     ивентов;
   - «Свой текст для этого ивента» — после сохранения открывается редактор писем этого ивента
     (карточка ивента, якорь «Письма»). Тексты по языкам покупателя (ru, en, cs, he, pl, uk, fr, de,
     it, es — одинаково на обоих сайтах) — в редакторе, не в мастере;
   - флажок «Отправить покупателям просьбу об отзыве после ивента» (по умолчанию — настройка
     сайта; письмо уходит через N дней, по умолчанию 2).
3. **Тур и промоутер на сайте** (только Lampyris, если есть туры/справочник) — тур
   (`lampyris_tour_id`) и промоутер из справочника сайта (реквизиты в строке «Организатор»
   на странице).

### 2.5 «Описание, валюта, продажи»

- Описание (текст, до 20 000 символов).
- Валюта — трёхбуквенный код (EUR, CZK, ILS…); пусто → по стране площадки / настройке.
- «Сразу открыть продажи» (по умолчанию включено) → публикация ивента и открытие товара
  на сайте. Без галочки ивент создаётся, но не публикуется.

### 2.6 Итог перед сохранением

Одна фраза, пересчитывается на лету, например:
`«Название», 16+. 2 сеанса: 15.10.2026 20:00 Зал, 80 мест; 17.10.2026 20:00 Ashdod Yam, 80 мест.
По очереди: Старт 99 ILS 3 бил. или до 30.09 → Обычный 199 ILS → На входе 249 ILS.`
Для одной категории: `Одна категория «Входной билет» 199 EUR, с 01.10 — 249 EUR.`
Для «все сразу»: `Все сразу: VIP 500 ILS × 20, Стандарт 250 ILS × 60.`
Кнопка: «Опубликовать» (создание) / «Сохранить изменения» (правка).

## 3. Что происходит при сохранении (путь «Продаём мы»)

1. Проверка прав оператора и формы (раздел 2). При ошибке форма возвращается с введёнными
   значениями и списком ошибок (хранится 15 минут).
2. Афиша: файл сохраняется в медиатеку сайта, его публичный URL идёт в пакет
   (`bigPosterUrl`) — Arena делает свою копию для электронного билета.
3. **По каждому сеансу, по порядку**:
   1. найти или создать товар WooCommerce (название = имя ивента, при нескольких сеансах
      `«Имя — ДД.ММ.ГГГГ»`; статус publish, если продажи открыты сразу, иначе
      `product_status` из настроек);
   2. `externalRef = wp:<site_slug>:product:<product_id>` (повторная отправка с тем же
      `externalRef` = правка, не копия);
   3. отправить пакет `POST /v1/organizations/{org}/imports/event-bundle` (раздел 4);
   4. первый сеанс создаёт ивент Arena; остальные присоединяются к нему через `actionId`
      из ответа первого;
   5. записать в мета товара ответ Arena (`_lops_arena_event_id`, `_lops_arena_session_id`,
      id категорий по именам, `bil24_action_id`, `bil24_action_event_id`, предупреждения,
      копию формы).
   Если сеанс N не сохранился — ошибка «Сеанс ДД.ММ.ГГГГ ЧЧ:ММ не сохранён. <причина>»,
   уже созданные товары запоминаются и повторная отправка использует их (без дублей).
4. Афиша ставится картинкой всех товаров сеансов.
5. Запоминаются ответы оператора (страна, город, площадка, возраст, промоутер, валюта).
6. Запускается синхронизация каталога сразу и ещё раз через 2 минуты (`kick_sync`).
7. Вкладки «Дополнительно» пишутся на все сеансы:
   - Vino — на сами товары;
   - Lampyris — на страницу мероприятия каждого товара (найденную по связи или по
     `bil24_action_event_id`, иначе создаётся черновик, который синхронизация потом дополняет);
   - Lampyris также: публикация страницы вместе с продажами, афиша, возраст, ACF-поля шаблона
     (6 фото, 4 видео, 3 партнёра), тур, промоутер сайта, метка «предстоящий/прошедший».
8. Переход: «Свой текст» писем → редактор писем ивента; иначе список ивентов с сообщением
   «Ивент создан и отправлен в Arena. Через минуту-две он появится в списке ниже.»
   (правка: «Изменения сохранены. На сайте они появятся через минуту-две.»).

## 4. Пакет Arena на один сеанс (event-bundle, source=arena)

Деньги в пакете — **крупные единицы** (199 = 199 ILS), дата сеанса `ДД.ММ.ГГГГ`, время
`ЧЧ:ММ` местное, границы окон — RFC 3339 с поясом площадки.

```json
{
  "source": "arena",
  "externalRef": "wp:vinoandco:product:13707",
  "action": {
    "actionId": 7040600,              // для 2-го и следующих сеансов и при правке
    "actionName": "Дегустация",
    "age": "18+",
    "promoterId": "",                 // "" = сама организация; uuid промоутера организации
    "description": "…",               // если заполнено
    "bigPosterUrl": "https://…/poster.jpg"
  },
  "actionEvent": { "actionEventId": 7040601, "day": "15.10.2026", "time": "20:00", "currency": "ILS" },
  "venue": { "arenaVenueId": "<uuid площадки организации>", "venueName": "Зал Нетания" },
  "categoryList": [ … ],
  "publish": true
}
```

`categoryList` — по режиму (каждая строка описывает **всю** форму категории, чтобы пересохранение
снимало то, что больше не действует):

| Режим | Строка категории |
|---|---|
| Одна категория | `{categoryPriceName, price, availability: <места зала>, nextCategoryIndex: -1, priceSchedule: [{validFrom, validTo, price}…]}` — окно графика от начала дня «с даты» до начала следующего окна (у последнего `validTo: ""`); `[]` снимает график |
| Все сразу | `{categoryPriceName, price, availability: <места категории>, nextCategoryIndex: -1, priceSchedule: []}` |
| По очереди | первая: `availability: <места зала>`, остальные `0`; `nextCategoryIndex: i+1` (у последней `-1`); `sellLimit: N` или `0` (снять), у последней `0`; `sellEndTime` = начало дня после «продаётся до»; `sellStartTime` следующей = тот же момент, **только если** у предыдущей нет лимита по числу (иначе следующая может открыться раньше даты) |

При правке у строки есть `categoryPriceId` — категория сохраняет id даже под новым именем
(форма помнит исходное имя).

Ответ Arena: `event_id`, `session_id`, `compat_ids` (actionId, actionEventId, id категорий),
`publication`, `warnings[]`. Предупреждения, которые показываются оператору:

| Код | Текст |
|---|---|
| `import.category_quantity_below_used` | Количество категории не изменено: нельзя поставить меньше, чем уже продано или забронировано. |
| `import.channel_publication_skipped` | Ивент не опубликован в канал сайта: ключ не привязан к каналу продаж. |
| `import.venue_matched_by_name` | Использована существующая площадка с таким названием. |
| `import.venue_timezone_kept` | У площадки уже другой пояс — оставлен прежний. |
| `import.category_sold_out` | Категория с количеством 0 создана закрытой. |
| `import.tier_not_in_payload` | Категории, которых нет в форме, закрыты (не удалены) — проданные билеты сохранены. |
| `import.publish_skipped` | Публикация не выполнена: ивент не прошёл проверку. |
| `import.poster_skipped` | Афиша не загружена — проверьте ссылку. |

Ошибки, переводимые на человеческий язык: `venue.duplicate_name`, `promoter.duplicate_name`,
`venue.invalid_timezone`; любой 403 → «У ключа ивент-центра нет права на это действие —
сообщите администратору Arena.»; `import.invalid_promoter`, `import.invalid_venue`,
`import.invalid_sell_limit` (лимит без следующей категории) — 422.

## 5. «Изменить» (правка существующего ивента)

Открывается из карточки ивента. Работает только для ивентов, созданных в ивент-центре (у товара
есть `_lops_arena_event_id` и свой `externalRef`), иначе «Этот ивент создан не в ивент-центре —
изменить его здесь нельзя.»

**Форма заполняется тем, что сейчас в Arena**, а не тем, что вводили в прошлый раз (цена,
поменянная в админке, уже сработавшая цепочка, отказ уменьшить количество — всё видно):
- `GET /v1/events/{event_id}` — название, возраст, промоутер, описание, опубликован ли;
- `GET /v1/organizations/{org}/venues` — пояса площадок;
- по каждому сеансу-товару: `GET …/events/{id}/sessions/{sid}` и `…/sessions/{sid}/tiers`;
  отменённые сеансы пропускаются; сеансы сортируются по времени начала;
- для одной категории — `…/tiers/{tid}/price-schedule` (график цены).

Правила восстановления:
- места сеанса = `capacity_override` или `capacity_total`;
- режим билетов: одна категория → «одна»; есть `next_tier_id` → «по очереди» (порядок — по
  цепочке от головы); иначе «все сразу» (места категории = `capacity`);
- «продаётся до» = день последней секунды окна категории; ступень, сохранённая только с
  числом билетов, получает окно до начала сеанса — такая дата не показывается как введённая;
- билеты в форме — **первого сеанса**; если у другого сеанса иные категории/цены,
  оператор видит предупреждение, а сохранение запишет билеты первого сеанса во все сеансы.

Ограничения правки:
- «Одна / несколько категорий» и «все сразу / по очереди» **не меняются** у созданного ивента;
- категорию, которая уже продаётся, убрать нельзя — можно поменять название, цену, количество
  или добавить новую (убранная из пакета категория в Arena закрывается, не удаляется);
- уже продающийся сеанс из формы не убирается; новый сеанс добавить можно (получит свой товар);
- проданные билеты не меняются: новая цена действует для следующих покупок;
- количество нельзя уменьшить ниже проданного и забронированного (предупреждение);
- «Кто продаёт» при правке не показывается (перевести ивент в режим партнёров нельзя).

Вкладки «Дополнительно» при правке заполняются с первой страницы ивента (галерея, видео,
партнёры, письма стандартные/свои, отзыв, тур, промоутер сайта).

## 6. Режим «Продают партнёры» / «Только анонс» (Lampyris)

Arena не вызывается, товар не создаётся. Создаётся страница мероприятия `past-event`.

Поля вместо сеансов и билетов:

| Поле | Правило |
|---|---|
| Дата, начало | обязательны (одна дата) |
| Страна, город, площадка | обязательны, свободный текст |
| Адрес | необязателен |
| Сайт организатора — где купить | только «партнёры»; http(s) |
| Цена «от» | число ≥ 0, необязательна |

«Партнёры»: нужна хотя бы одна ссылка — сайт организатора или партнёр во вкладке «Где ещё
купить» («Укажите хотя бы одну ссылку, где продаются билеты.»). Название, возраст, описание,
промоутер, афиша, валюта, публикация — из общих разделов. На страницу пишутся: ссылка
организатора → кнопка «Купить на сайте организатора», до 3 партнёров, фото/видео, возраст,
цена «от» с валютой, тур, промоутер, метка «предстоящий». Галочка «сразу открыть продажи»
публикует страницу, без неё — черновик. Сообщения: «Страница мероприятия опубликована и видна
на сайте. Arena в этом ивенте не участвует.» / «…сохранена черновиком — на сайте её пока не видно.»
Замечание: страница создаётся на языке WPML по умолчанию (английский); переводы — отдельно.

## 7. Что делает Arena с тем, что задал мастер

- **Цепочка категорий** (`ticket_tier_chain`, миграции 0112/0114): голова владеет местами,
  следующие закрыты. Фоновая задача `tier.chain_sweep` (каждые 30 с) передаёт свободные места
  следующей категории и открывает её, когда у текущей прошла дата **или** распроданы её
  N билетов (продано + в брони = лимит). Число мест в зале не меняется. При раннем переходе
  следующая категория начинает продаваться сразу (сдвигается начало продаж).
- **Ступень по количеству** (`sell_limit`): у продающейся категории ровно N мест, остальное
  ждёт в следующей закрытой.
- **Перетекание заказа**: если покупатель берёт больше, чем осталось в ступени, заказ
  одним платежом забирает остаток по текущей цене и недостающее по следующей
  (`CheckGALinesSellable`; сайт делит строку корзины по `nextCategoryPriceId` из каталога).
- **Подсказка «осталось N по этой цене»** — на сайте, только при остатке ≤ 10 (настройка
  сайта `chain_left`, 0 = никогда): организаторы не любят показывать непроданное.
- **График цены** (одна категория): цена меняется в заданные дни, место и название те же.
- **Промоутер** — таблица `org_promoters` + связь `event_promoters`; пустая связь = организация.
- **Площадка** выбирается по `arenaVenueId` (UUID площадки организации), пакет её не меняет.
- Места с номерами (схема зала) мастером **не** поддерживаются (волна 2 плана 27.09).

## 9. Чего в мастере нет (сейчас)

- рассадка по схеме зала;
- разные категории у разных сеансов при создании (только правкой в админке/позже);
- отмена/удаление сеанса или ивента;
- смена режима продажи у созданного ивента;
- тексты писем — только в отдельном редакторе ивента (мастер лишь переключает «свои»);
- наборы фото/видео по языкам (пишется базовый язык);
- автоматическая картинка 1200×630 для соцсетей (запланирована);
- поиск ивентов Arena, созданных не этим сайтом.

## 10. Что важно для бота (факты, не решения)

- Мастер — это **последовательность вопросов с ветвлением**; в боте она ложится на шаги
  естественно: 2.0 → 2.1 → 2.2 (цикл по сеансам) → 2.3 (ветка по режиму, цикл по категориям)
  → 2.4 → 2.5 → итог 2.6 → подтверждение.
- Шаги со **справочниками из Arena**: промоутеры, страны, города, площадки — нужен выбор из
  списка + создание нового с проверкой дублей (раздел 2.2, «Новая площадка»).
- **Афиша** — файл с проверкой формата; в Telegram фото сжимается, поэтому для проверки
  ширины ≥ 1080 нужен документ, а не «фото».
- **Сохранение не атомарно**: N сеансов = N запросов; повтор должен переиспользовать уже
  созданные товары/сеансы (`externalRef` идемпотентен).
- Товары WooCommerce и страницы Lampyris создаёт **сайт**, не Arena; материалы/письма/тур живут
  только на сайте.
- «Изменить» читает состояние из Arena и подчиняется ограничениям раздела 5.
- Все пользовательские тексты мастера — русские; сайты многоязычные (покупатель видит свой язык).
