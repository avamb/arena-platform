| Доставка | Местный курьер (название на записи неразборчиво, «IDM»), заявка заводится вручную в его личном кабинете, поля по одному. Анна сейчас фотографирует заказ и пересылает логисту. Минимум: сообщение с реквизитами в том же порядке, что поля кабинета, чтобы копировать построчно. Интеграция по API только если кабинет её допускает, Андрей посмотрит кабинет. |

Уточнение к разбору 22.10: в Shopify заказов POS нет, потому что терминал PayPlus
работает отдельно от Shopify, на мероприятиях, не через канал Point of Sale. Это
не отменяет вывод, что Shopify POS не использовался, но отменяет свободный выбор
провайдера: терминал привязывает Vino&Co к PayPlus.

Следствие для архитектуры: магазин на платформе должен принимать PayPlus как
hosted-checkout провайдера организатора (третий после Stripe и Flitt), а AllPay
остаётся отдельной задачей для других организаторов. Детали API в §4.

## 4. API PayPlus и терминал (исследование 26.10, docs.payplus.co.il)

Индекс документации: `https://docs.payplus.co.il/llms.txt`, каждая страница
читается как `.md`.

**Вывод: PayPlus ложится на наш hosted-checkout образец (Stripe, Flitt) без
новой архитектуры.** Карта на наши сущности:

| Наше | PayPlus |
|---|---|
| ключи организатора в `payment_provider_configs.secrets` | `api-key`, `secret-key` (заголовки каждого запроса) плюс `payment_page_uid` страницы, настроенной в дашборде PayPlus |
| создание hosted-страницы | `POST /api/v1.0/PaymentPages/generateLink`: `amount`, `currency_code` (ILS), `refURL_success/failure/cancel/callback`, `send_failure_callback=true`, `expiry_datetime` в минутах (наше окно оплаты), `customer{name,email}`, `items[]` |
| `provider_payment_id` | `data.page_request_uid` из ответа; в колбэке он же `transaction.payment_request_uid` |
| наш `checkout_session_id` | `more_info` (возвращается во всех колбэках и редиректах, как у Flitt `order_id`) |
| `provider_charge_ref` (для возврата) | `transaction.uid` из колбэка |
| вебхук | `refURL_callback` на `POST /v1/public/payment-webhook/{config_id}`; подпись в заголовке `hash` = base64(HMAC-SHA256(secret_key, тело)), плюс `user-agent: PayPlus`. Проверять по СЫРЫМ байтам тела через `hmac.Equal`; совпадение с пересериализованным JSON из примера доки не подтверждено, проверить на стенде |
| успех | `transaction.status_code == "000"`; остальные коды через `GET /ErrorCodes/terminal_uid={uid}` |
| дедуп | по `transaction.uid` (повторы и ретраи в доке не описаны) |
| возврат, в т. ч. частичный | `POST /Transactions/RefundByTransactionUID` {`transaction_uid`, `amount` ≤ исходной}; в тот же день до депозита (23:00) есть `Transactions/Cancel`. Работа Refund для обычного J4-списания не подтверждена, проверить |
| проверка статуса | `POST /Transactions/View` по `transaction_uid` или `more_info` |
| `VerifyCredentials` | дешёвый вызов с ключами, например `Device/List` или `Dictionary/MyTerminals` (выбрать на стенде) |
| тестовый контур | `https://restapidev.payplus.co.il/api/v1.0/`, прод `https://restapi.payplus.co.il/api/v1.0/`; `PAYPLUS_API_BASE_URL` как seam, запрещённый в production, как у Flitt. Тестовые карты 5326-1402-8077-9844 (успех), 5326-1402-0001-0120 (отказ) |
| редирект покупателя | через наш `/v1/public/payment-return` как у Flitt: редирект успеха не подписан, доверять только колбэку |
| методы на странице | credit-card, bit, apple-pay, google-pay, paypal через `allowed_charge_methods`, включаются настройкой страницы и терминала; рассрочка `payments`, `hide_payments_field` |
| токены и подписки | `create_token=true` → токен карты, списание `Transactions/Charge` с `use_token`; рекуррент `charge_method=3` + `recurring_settings`, нужен модуль у PayPlus. Для винного клуба второй этап |
| счета | у PayPlus свой Invoice+: `initial_invoice=true` в generateLink, документ приходит в `invoice{}` колбэка. Это может заменить интеграцию с Green Invoice, если Vino&Co устроит Invoice+; спросить Анну |

Валюты и языки страницы в доке не перечислены (не подтверждено; плагин заявляет
ru/en, `language_code` по умолчанию he). Для Einat Winery нужен только ILS.

**Терминал.** Терминалы PayPlus это Android EMV-устройства (FEITIAN, UROVO, PAX)
и приложение Tap on Phone. `terminal_uid`, `cashier_uid` и `Device/List` общие
сущности аккаунта, а `POST /Device/TransactionByDevice` создаёт транзакцию,
проводимую на устройстве. Значит, терминал и наш онлайн-магазин живут в одном
аккаунте PayPlus, и позже можно отправлять сумму заказа с самовывозом на терминал
прямо из нашей карточки заказа (не подтверждено на практике). Для переноса это не
нужно: терминал продолжает работать как сейчас, мы его не трогаем.

**AllPay** терминалов и tap-on-phone не предлагает (только ссылки и QR), значит
решение Анны остаться на PayPlus обосновано. Цены PayPlus не публичны; AllPay для
сравнения: 50 ₪/мес, 1,2–1,4 % локально, 1 ₪ за платёж.

- [ ] От Анны: ключи API и `payment_page_uid` боевого аккаунта Vino&Co (или
  создать отдельную платёжную страницу для магазина в их дашборде).
- [ ] Проверить на стенде четыре неподтверждённых пункта: подпись по сырым байтам,
  где лежит токен в колбэке, Refund для J4, языки и валюты страницы.
