## B. Отклонено или смягчено — не делаем (или только тест)

- **Менеджер приглашает владельца через API.** `membership.grant` у `organizer` нет (0116 дал только `org_admin`, 0129 оставил owner-only). Добавить только негативный тест.
- **Часовой пояс площадки пуст → UTC.** С миграции 0118 `venues.timezone` NOT NULL и не пуст. Остаётся защитный `LoadLocation`; ничего не меняем.
- **Идемпотентность отмены/переноса сеанса.** Сервер уже защищён: повторная отмена «nobody is told twice» (`sessionchange/kinds.go:76`), перенос без изменений не пишет журнал. Ключ идемпотентности не нужен. Пересчёт impact перед записью — желательно, но дёшево не нужно.
- **Нулевая сумма возврата → «No money returned».** Уже есть подстановка суммы из payload события (`salesnotify.go:238-245`); остаток — в A5.
- **Решения по заявкам «не более одного раза»** (`BotClaimNotices`): решение владельца из AGENTS.md («потерять одно сообщение лучше, чем повторить»). Не меняем без отдельного решения; при желании — ack-схема как отдельная задача.
- **Граница суперадмина (константа X-Admin-Reason, секрет JWT в процессе бота).** Это дизайн текущей схемы (бот минтит JWT сам). Перенос в обмен токена на сервере — отдельная архитектурная задача, не баг.
- **Перебор на `/bot/invitations/accept`, перечисление аккаунтов через приглашение, 404 vs 422 на accept.** 256-битный код, токен сервиса; влияние минимальное. Rate limit по IP — проверить на ingress, в код не добавлять.
- **Нет дедупликации `update_id`.** Offset ведёт библиотека; реальные случаи — двойной тап, они защищены состоянием или сервером (`ExternalRef`). Не делаем.
- **Один воркер/лимит на аккаунт.** Известный осознанный выбор (`WithWorkers(1)`); см. B-пункт ниже о дедлайне.
