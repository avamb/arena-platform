# Форматированный текст (RT-02/RT-03) — ранбук выката

Спецификация: `08_architecture/44_rich_text_editor_spec_ru.md`. Ветка `feat/rt-02-richtext-storage`.
Миграция: `0168_rich_text.sql` (колонки `events.description_format`, `event_email_notes.note_format`).

## 0. Что меняется для сайтов

Сайты Lampyris и Vino записывали описания через `source=bil24` как HTML, и в базе они лежат с признаком `text`.
Шлюз Bil24 (`GET_ALL_ACTIONS`) теперь узнаёт такие строки по тегам (`richtext.LooksLikeHTML`) и отдаёт их как `art`.
Сайт получает свой HTML обратно, очищенный, с абзацами как в WordPress. Теги не экранируются и после выката, и до backfill.
Решение принято в PR: вариант (б) ревью, правило в шлюзе. Backfill для сайтов нужен позже, чтобы хранить правильный признак.

## 1. До выката

1. Посчитать строки с HTML по организациям. Колонки признака ещё нет, поэтому запрос без неё:

```sql
SELECT org_id, count(*) AS events_with_html
FROM events
WHERE description ~* '</?(p|br|strong|b|em|i|u|a|ul|ol|li|h[1-6]|blockquote|div|span)(\s[^<>]*)?/?>'
GROUP BY org_id
ORDER BY events_with_html DESC;
```

2. То же для переводов:

```sql
SELECT count(*) AS translations_with_html
FROM i18n_text
WHERE namespace = 'event.description'
  AND value ~* '</?(p|br|strong|b|em|i|u|a|ul|ol|li|h[1-6]|blockquote|div|span)(\s[^<>]*)?/?>';
```

3. Записать числа в PR. Организации с большим числом строк — это организации сайтов (Lampyris, Vino).
4. Сделать бэкап базы (`deploy/BACKUP_RESTORE_RUNBOOK.md`).

## 2. Порядок выката

1. Миграция `arena-migrate up` (0168). Колонки добавляются с `DEFAULT 'text'`, существующие строки не меняются.
2. api, worker, bot (один тег образа).
3. `tickets-page` (страница продаж).
4. `admin-web`.

Старый API с новой страницей продаж работает: страница читает старое поле `description`.
Новый API со старой страницей показывает `description` как раньше.

## 3. Что проверить на стенде

- Страница продаж: событие с `art` (ссылки, заголовок, список) и событие со старым текстом (`**жирный**`, список через «- »).
- Шлюз `GET_ALL_ACTIONS` для Lampyris и Vino: описания приходят HTML, без `&lt;p&gt;`, абзацы на месте, ссылки с `rel` и `target`.
  Строка `text` с «a < b» остаётся текстом.
- admin-web: карточка события показывает форматирование. В форме видна подсказка про потерю ссылок и заголовков.
  Очистка поля описания действительно очищает описание.
- Бот: правка только даты у события с форматированным описанием и переводом `en`. Базовое описание не меняется.
  Описание, набранное в боте, принимается.
- Письмо покупателю с заметкой организатора (список, ссылка) и тестовое письмо из ивент-центра.

## 4. Backfill (после выката)

Команда не входит в образ. Запускать из чекаута того же коммита с доступом к базе:

```
DATABASE_URL=... JWT_SIGNING_SECRET=x go run ./apps/backend/cmd/arena-richtext-backfill --org <org_id> --report report.md
```

1. Dry-run (режим по умолчанию) на стенде, потом на проде. Отчёт без текстов: id, локали, длины, причины.
2. Отчёт читает владелец. Строки с причиной `literal_tags` остаются как есть: это HTML сайтов с признаком `text`.
3. `--apply` по одной организации (`--org`). Каждое событие в своей транзакции, старое значение копируется в `richtext_backfill_backup`.
4. Большие базы — порциями: `--limit N`, следующий запуск `--after <event_id>` (id печатается в конце прогона). Таймаут одного прогона 2 часа.
5. `--html-as-art` только для организаций сайтов и только после чтения отчёта. Абзацы без `<p>` сохраняются (как `wpautop`).
6. Повторный запуск ничего не меняет: берутся только строки с признаком `text`.
7. Резервные копии старше нужного срока: `--purge-backup-older-than <дни> --apply`.

## 5. Откат

- Backfill: `--rollback <run_id> --apply` (без `--apply` это проверка). Можно ограничить `--org`.
  Текст, записанный после прогона, не трогается: событие остаётся как есть.
- Код: вернуть предыдущий тег образа. Данные в формате `art` старый код покажет тегами, поэтому откат кода делать только вместе с конвертацией.
- Миграция `down` отказывает, пока есть строки `art` в `events` или `event_email_notes`.
  Сначала нужно перевести их в текст и поставить признак `text`, потом `down`.
