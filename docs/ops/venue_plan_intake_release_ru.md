# Приём схем зала: что нужно для выката на прод

Документ для выката ветки `claude/plans-integration-8d255b` (PR 412) на прод. Проверено на стенде 12.11.2026.

## 1. Переменные окружения

| Переменная | Кому | Зачем | Что будет без неё |
|---|---|---|---|
| `EVENTS_TELEGRAM_BOT_TOKEN` | воркеру (блок `x-worker-env`), кроме бота | Воркер отправляет администраторам платформы личные сообщения в Telegram: новая заявка на схему зала, новая страна, новая заявка организатора | Сообщения идут только письмом. В логе воркера строка `adminnotify: EVENTS_TELEGRAM_BOT_TOKEN is not set on the worker` |
| `ACTIVE_LOCALES: "en,ru"` | api (общий блок `x-arena-env`) | Названия стран мира и городов по-русски в ответах `world-countries` и каталога площадок | Названия приходят только по-английски |

| `VENUE_GEN_URL`, `VENUE_GEN_TOKEN` | воркеру (блок `x-worker-env`) | Воркер отдаёт заявку на схему генератору. Адрес: внутренний адрес контейнера генератора, например `http://venue-generator:8090`. Токен тот же, что у контейнера генератора | Генератор выключен: каждая заявка сразу уходит администратору с причиной `no_generator`. Если задан только адрес без токена, генератор тоже выключен, в логе воркера `generator_configured=false` |

На проде секреты разделены по контейнерам: токен бота сейчас есть только у контейнера `bot`. Воркеру его нужно добавить отдельной строкой `EVENTS_TELEGRAM_BOT_TOKEN: ${EVENTS_TELEGRAM_BOT_TOKEN}` в блок `x-worker-env`. Значение то же, что у бота. Воркер с этим токеном только отправляет сообщения и не опрашивает Telegram, поэтому конфликта двух получателей нет.

На стенде обе переменные поставлены 12.11.2026. Токен стенда принадлежит тестовому боту `ArenaAppTestZone_bot`.

## 2. Миграции

Две новые миграции: `0216_venue_plan_intake.sql` и `0217_venue_plan_notice_escalated.sql`. Они только добавляют таблицы, столбцы и одно значение вида уведомления. Перед выкатом снимите дамп базы.

## 3. Генератор схем

С волны 2 воркер сам отдаёт заявку генератору. Из таблицы Excel генератор строит первый черновик, и организатор видит его без администратора. PDF и изображения, как и раньше, уходят администратору с причиной `unsupported_format`.

Чтобы это работало на проде, там нужен контейнер генератора и две переменные воркера из раздела 1. Без них приём схем работает по-старому: каждую заявку берёт администратор. Как генератор поставлен на стенд (образ, лимит памяти 1 ГБ, без опубликованного порта, токен в файле на сервере), написано в `docs/ops/venue_generator_staging_install_2026-11-12_ru.md`.

Проверка на стенде 13.11.2026: заявка с таблицей Excel из набора генератора получила черновик за 5 секунд (25 мест, 5 рядов, 2 сектора), заявка с PNG ушла администратору. Пик памяти генератора 105 МБ.

## 4. Библиотека схем

Загрузчик `ops/forzum-library/loader.py` оставляет загруженную схему активной. Проверку схемы и площадки делает администратор в админке, раздел «Seating plans».

## 5. Проверка после выката

1. `/v1/info` показывает новый коммит и `supported_locales` с `ru`.
2. `GET /v1/geo/world-countries?lang=ru` отвечает 200 и отдаёт 249 стран.
3. Маршруты `/v1/organizations/{org_id}/plan-intakes` и `/v1/admin/plan-intakes` без токена отвечают 401.
4. Тестовая заявка на схему в организации ABH TEAM: администратор получает сообщение в Telegram и письмо.
5. В логе воркера нет строки `EVENTS_TELEGRAM_BOT_TOKEN is not set on the worker`.
