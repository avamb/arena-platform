# Выкат веб-ивент-центра на events.arenasoldout.com

Спецификация: `08_architecture/37_web_event_center_ru.md`, разделы 4.2 и 10. Решения владельца от 14.10.2026: поддомен `events.arenasoldout.com` утверждён, ссылки писем о пароле для организаторов ведут в веб-ивент-центр.

## 1. Что получится

1. Сайт `https://events.arenasoldout.com` — веб-ивент-центр для организаторов. Это отдельное приложение Dokploy, как `tickets-page`.
2. Организатор (владелец, менеджер или агент организации без платформенной роли) получает письмо о пароле со ссылкой на `https://events.arenasoldout.com/reset-password` или `/accept-invite`. Письмо написано на его языке (en, ru, es) и объясняет каждый шаг.
3. Платформенный пользователь (суперадмин, оператор, поддержка) по-прежнему получает ссылку в админку (`APP_PUBLIC_URL`).

## 2. Перед началом

1. PR с этой задачей слит в master, CI master зелёный, образ `ghcr.io/avamb/arena-api:<sha>` опубликован.
2. Вы вошли в панель Dokploy (`app.andreevmaster.com`) и в Cloudflare (зона `arenasoldout.com`).
3. Порядок шагов важен. Адрес для писем (`EVENT_CENTER_PUBLIC_URL`) включается ПОСЛЕДНИМ, когда сайт уже открывается. Иначе организатор получит ссылку на сайт, которого ещё нет.

## 3. Шаги

### Шаг 1. Запись DNS в Cloudflare

1. Откройте Cloudflare, зону `arenasoldout.com`, раздел DNS.
2. Откройте запись `tickets` и запишите её тип и значение (адрес сервера arena-prod).
3. Нажмите «Add record».
4. Тип и значение — как у записи `tickets`. Name: `events`. Proxy status: Proxied (оранжевое облако), как у `tickets` и `api`.
5. Нажмите «Save».

### Шаг 2. Приложение в Dokploy

1. Откройте проект `arena`, окружение `production`.
2. Откройте приложение `tickets-page` и посмотрите его настройки: сервер, источник, способ сборки. Новое приложение настраивается так же.
3. Нажмите «Create Service», затем «Application». Название: `event-center`.
4. Источник: GitHub, репозиторий `avamb/arena-platform`, ветка `master`.
5. Сервер: тот же, что у `tickets-page` (arena-prod).
6. Build Type: Dockerfile. Docker File: `apps/event-center/Dockerfile`. Docker Context Path: `.` (корень репозитория).
7. Аргумент сборки (поле Build Args / Build-time Arguments, там же, где у `tickets-page`): `VITE_API_BASE_URL=https://api.arenasoldout.com`. Без косой черты в конце. Без этого аргумента сборка остановится с ошибкой: так задумано.
8. Переменные окружения во время работы не нужны. Секретов у приложения нет.
9. Вкладка Domains: Host `events.arenasoldout.com`, Path `/`, Container Port `8080`, HTTPS включён, Certificate `Let's Encrypt`.
10. Нажмите «Deploy». Сборка занимает 2–4 минуты. Проверка здоровья встроена в образ (`GET /health`).

### Шаг 3. Проверка сайта

1. Откройте `https://events.arenasoldout.com/health`. Должно быть `ok`.
2. Если Cloudflare показывает ошибку 526, у Traefik ещё нет сертификата. Подождите 2 минуты и обновите страницу.
3. Если ошибка 526 не уходит 5 минут, нажмите «Deploy» у приложения ещё раз: Traefik запросит сертификат заново. Если и это не помогло, переключите запись `events` в Cloudflare на «DNS only» (серое облако), дождитесь страницы, потом верните «Proxied».
4. Проверьте режим SSL зоны в Cloudflare: раздел SSL/TLS, Overview. Нужен режим «Full (strict)». Так Cloudflare проверяет сертификат сервера и не пускает подменённый.
5. Если режим не «Full (strict)», сначала убедитесь, что `https://events.arenasoldout.com/health` отвечает `ok`, то есть сертификат Let's Encrypt уже выпущен. Только после этого включите «Full (strict)». Если включить его раньше, сайт будет отвечать 526.
6. Режим действует на всю зону, а не только на `events`. Если в зоне есть адрес без настоящего сертификата, он после переключения ответит 526. Проверьте `api`, `tickets` и главную страницу сразу после переключения.
7. Запустите проверку из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File apps\event-center\scripts\check-live.ps1
```

На этом шаге строки про заголовки должны быть `OK`. Строки про CORS будут `FAIL`: API ещё не знает новый адрес. Это исправит шаг 4.

### Шаг 4. CORS и адрес для писем на arena-api

> Внимание. Переменная во вкладке Environment панели НЕ доходит до контейнеров сама. Compose `backend-prod` перечисляет переменные явно в блоке `x-arena-env`. Правьте именно этот блок.

1. Откройте compose `backend-prod`, вкладку с текстом compose.
2. Сохраните копию текущего текста compose (на случай отката).
3. В блоке `x-arena-env` найдите строку `CORS_ALLOWED_ORIGINS`. Добавьте в конец значения через запятую: `https://events.arenasoldout.com`. Прежние адреса не удаляйте.
4. В том же блоке добавьте строку: `EVENT_CENTER_PUBLIC_URL: "https://events.arenasoldout.com"`. Значение не секретное.
5. Замените тег образа на sha из раздела 2 во всех строках `image: ghcr.io/avamb/arena-api:` (api, worker, migrate, bot) и в `APP_COMMIT`.
6. Нажмите «Save», затем «Deploy».
7. Проверьте, что api, worker и bot в состоянии healthy, а migrate завершился с кодом 0.

### Шаг 5. Итоговая проверка

1. Запустите проверку ещё раз. Все строки должны быть `OK`:

```powershell
powershell -ExecutionPolicy Bypass -File apps\event-center\scripts\check-live.ps1
```

2. Откройте `https://events.arenasoldout.com` и войдите под учётной записью организатора (не суперадмина). Должен открыться выбор организации.
3. Проверьте письмо. Откройте `https://events.arenasoldout.com/forgot-password` и введите e-mail тестового организатора без платформенной роли. В письме ссылка должна вести на `https://events.arenasoldout.com/reset-password?token=…`.
4. Откройте ссылку, задайте пароль, войдите с ним.
5. Для сравнения запросите письмо для учётной записи суперадмина. Ссылка должна вести в админку (`APP_PUBLIC_URL`).
6. Проверьте кнопку в боте (задача WEB-AUTH-2, миграция 0151 уже применена шагом 4). Войдите в бот под организатором, откройте «☰ Меню» и нажмите «🌐 Открыть в браузере». Бот пришлёт ссылку на `https://events.arenasoldout.com/login/link#code=…`. Откройте её: должен открыться выбор организации.
7. Через полминуты бот пришлёт сообщение «Вы вошли в веб-ивент-центр…» с кнопкой «🚪 Выйти везде». Нажмите её. Бот ответит «Готово». Обновите страницу веба через 15 минут: она попросит войти снова. Вход в админку при этом не закрывается.
8. У суперадмина кнопки «Открыть в браузере» в боте нет. Так задумано.

## 4. Откат

1. Письма снова ведут в админку, а кнопка «Открыть в браузере» в боте отвечает «веб ещё не подключён», если убрать строку `EVENT_CENTER_PUBLIC_URL` из `x-arena-env` (или оставить пустое значение) и нажать «Deploy» у `backend-prod`. Код и сайт трогать не нужно.
2. Сайт можно остановить кнопкой «Stop» у приложения `event-center`. Перед этим уберите `EVENT_CENTER_PUBLIC_URL` (пункт 1), иначе письма поведут на остановленный сайт.

## 5. Что проверяет CI

1. Задача `event-center-build`: vitest, сборка, Playwright smoke (включая страницы `/reset-password` и `/accept-invite`), сборка образа, ожидание `healthy`, `scripts/check-headers.sh` на контейнере, тот же smoke против контейнера с включённым CSP и журнал nginx: в нём есть путь `/reset-password`, но нет токена и адреса из ссылки.
2. Go: `authemail` (выбор адреса и тексты писем), `config` (на проде `EVENT_CENTER_PUBLIC_URL` — только адрес вида `https://хост` без пути, запроса и фрагмента), интеграционный тест `TestPGRecipients_OrganizerOrPlatformUser` (кто организатор, кто платформенный пользователь).
