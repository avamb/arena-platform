## 3. PR #411: решение принято, PR едет

Решение владельца 13.11.2026:

- «ArenaSoldOut.com» — название платформы. Платформа не продаёт билеты. Она продаёт услуги платформы
  организаторам. Билеты продаёт организатор.
- Там, где документ или письмо называет платформу, пишется «ArenaSoldOut.com».
- Письма с билетом и пригласительные уходят с адреса `ticket@arenasoldout.com`.
- Имя отправителя в письме покупателю: «Если указан промоутер, то промоутер, если не указан, значит
  организация». Правило действует для всех организаций, с white label и без него.
- Письма без организации (вход, пароль, приглашение в команду) идут под именем «ArenaSoldOut».

Что сделано в ветке PR #411 (коммиты `55a37cd1`, `00904229`, `ef43496a`):

- Название платформы в юридических документах — «ArenaSoldOut.com». Красный тест
  `legaldocs.TestPlatformSellerName_MatchesTheLetters` стал зелёным.
- Новая переменная воркера `TICKET_EMAIL_FROM`: адрес отправителя писем с билетом и пригласительных.
  Проверенный собственный отправитель организации главнее.
- Новая переменная воркера `EMAIL_FROM_NAME`, по умолчанию «ArenaSoldOut»: имя отправителя для писем с
  адреса платформы, у которых нет своего имени.

- Имя отправителя писем покупателю: промоутер мероприятия, иначе организация, для каждой организации.
  Раньше имя подставлялось только организациям с white label. Письмо магазина со своим названием магазина
  его сохраняет.

Проверено на стенде 13.11 около 19:40, сборка `ddc7b8c9`, организация ABH TEAM, по записи
`email_letters.from_address`:

## 6. Генератор схем на проде: где его ставить

Генератор — отдельный контейнер `apps/venue-svg-generator` (Python). К нему обращается только воркер, по
внутренней сети. Порт наружу не публикуется. Как он поставлен на стенд, написано в
`docs/ops/venue_generator_staging_install_2026-11-12_ru.md`.

Замеры на стенде: пик памяти 105 МБ на таблице Excel из тестового набора, по записи установки на стенд пик
на настоящих файлах около половины лимита 1024 МБ. Одна заявка за раз. Автоматически строится черновик только
из таблицы Excel. PDF и изображения уходят администратору.

| | Вариант А: рядом со стеком прода на `arena-prod` | Вариант Б: отдельный сервер |
|---|---|---|
| Сеть | Внутренняя сеть compose, порт закрыт | Нужен закрытый канал между серверами или порт с ограничением по адресу |
| Риск для продаж | Генератор делит память с базой и API. Ограничивается лимитом 1024 МБ и `oom_score_adj 500`: при нехватке памяти система убивает его первым | Никакого |
| Стоимость и работа | Ноль новых серверов, установка как на стенде | Новый сервер или перенос на `lead-parser`, где уже живут клиентские сайты |
| Отказ | Заявка уходит администратору, продажи не затронуты | То же, плюс зависимость от сети между серверами |

**Условие включения автогенерации на проде.** Ночью 13.11 ручная проверка стенда нашла дефект: черновик
генератора на экране проверки был залит чёрными кляксами. Причина: генератор писал SVG в единицах сетки
(холст 9 на 10) с обводкой места толщиной 3. Исправлено в генераторе: расстояние между местами 24, обводка
1, защита помечает непригодный рисунок и отдаёт заявку администратору. Пока исправленный образ генератора не
проверен глазами на стенде на настоящих файлах, **`VENUE_GEN_URL` и `VENUE_GEN_TOKEN` воркеру прода не
задавать**. Всё остальное выкатывается без генератора. Образ генератора для прода собирается из коммита с
исправлением, не раньше.

**Рекомендация: вариант А, но вторым шагом, не в ночь основного выката.** Основной выкат идёт с пустыми
`VENUE_GEN_URL` и `VENUE_GEN_TOKEN`: приём схем работает, каждую заявку берёт администратор, как на стенде до
волны 2. Генератор ставится отдельно, когда видно, что на `arena-prod` свободно не меньше 2 ГБ памяти при
обычной нагрузке. Если свободно меньше 2 ГБ, выбирать вариант Б или оставить генератор только на стенде.

Память прода агент не смотрел. Команда для владельца (только чтение):

```powershell
ssh arena-prod "free -m; docker stats --no-stream --format '{{.Name}} {{.MemUsage}}'"
```

Смотреть столбец `available` в строке `Mem`.
