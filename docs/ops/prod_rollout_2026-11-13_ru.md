## 3. PR #411: красный тест и решение

Тест `legaldocs.TestPlatformSellerName_MatchesTheLetters` падает:
`PlatformSellerName "Arena Platform" != templates.PlatformLegalName "ArenaSoldOut.com"`.

Причина. Тест требует, чтобы продавец в условиях продажи и продавец в письмах назывались одинаково. Это имя
подставляется, когда платформа сама продаёт билет как продавец (канал `merchant_of_record`), и в письмах
организации без юридического названия. PR #411 поменял имя в письмах на `ArenaSoldOut.com`. Имя в условиях
продажи (`apps/backend/internal/platform/legaldocs/legaldocs.go`, константа `PlatformSellerName`) автор PR
оставил владельцу: это текст юридического документа.

Исправление занимает одну строку: `const PlatformSellerName = "ArenaSoldOut.com"`. После него тест зелёный.
Агент его не внёс: ветка PR #411 чужая, а текст условий продажи меняет только владелец.

Решение по умолчанию: **PR #411 в этот выкат не входит**, пока владелец не скажет, как называть продавца в
условиях продажи. Варианты:

1. «ArenaSoldOut.com» и в условиях продажи. Тогда в ветку PR #411 идёт строка выше, CI зеленеет, PR едет
   вместе со всеми.
2. Юридическое название компании. Тогда его нужно дать, и та же строка меняется в обоих местах.

Без PR #411 остальное выкатывается как есть: другие ветки от него не зависят. На стенде PR #411 стоит,
письма с новым брендом там проверены, красный тест на работу стенда не влияет.

## 5. Переменные окружения

В compose `backend-prod` переменная доходит до контейнера, только если она записана строкой в блоке этого
сервиса. Значение из вкладки Environment само в контейнер не попадает.

| Переменная | Блок compose | Значение | Обязательна | Что будет без неё |
|---|---|---|---|---|
| `EVENTS_TELEGRAM_BOT_TOKEN` | `x-worker-env` (у бота уже есть) | `${EVENTS_TELEGRAM_BOT_TOKEN}`, токен боевого бота | Нет | Администраторы платформы получают новую заявку организатора и заявку на схему только письмом. В логе воркера `adminnotify: EVENTS_TELEGRAM_BOT_TOKEN is not set on the worker` |
| `ACTIVE_LOCALES` | `x-arena-env` (общий) | `"en,ru"` | Нет | Названия стран и городов в выборе площадки приходят только по-английски |
| `VENUE_GEN_URL` | `x-worker-env` | `http://venue-generator:8090` (внутренний адрес контейнера генератора) | Нет | Генератор выключен: каждая заявка на схему сразу уходит администратору с причиной `no_generator` |
| `VENUE_GEN_TOKEN` | `x-worker-env` | `${VENUE_GEN_TOKEN}`, тот же секрет, что у контейнера генератора | Нет | То же. Если задана только одна из двух переменных, генератор выключен, а воркер при старте пишет предупреждение |
| `EVENT_CENTER_PUBLIC_URL` | `x-bot-env` | `https://events.arenasoldout.com` | Нет | В боте экран «У меня уже есть организация» без кнопки «Открыть ивент-центр» (из выпуска F-007) |

Воркер с токеном бота только отправляет сообщения и не опрашивает Telegram. Конфликта с ботом нет.

**Внимание к `ACTIVE_LOCALES`.** Эта настройка включает русский не только для названий стран. С ней API
начинает отвечать по-русски на запросы с заголовком `Accept-Language: ru`: тексты ошибок, названия из
справочников. Сейчас прод отвечает всем по-английски. На стенде `en,ru` стоит с 12.11, замечаний нет. Если
владелец не хочет менять язык ответов прода в эту ночь, переменную можно не ставить: всё работает, названия
стран будут английскими.

Токен стенда принадлежит тестовому боту `@ArenaAppTestZone_bot`. На прод он не переносится, и наоборот.

## 6. Генератор схем на проде: где его ставить

Генератор — отдельный контейнер `apps/venue-svg-generator` (Python). К нему обращается только воркер, по
внутренней сети. Порт наружу не публикуется. Как он поставлен на стенд, написано в
`docs/ops/venue_generator_staging_install_2026-11-12_ru.md`.

Замеры на стенде: пик памяти 105 МБ на таблице Excel из тестового набора, по записи установки на стенд пик
на настоящих файлах около половины лимита 1024 МБ. Одна заявка за раз. Автоматически строится черновик только
из таблицы Excel. PDF и изображения уходят администратору.

| | Вариант А: рядом со стеком прода на `arena-prod` | Вариант Б: отдельный сервер |
|---|---|---|
| Сеть | Внутренняя сеть compose, порт закрыт | Нужен закрытый канал между серверами или порт с ограничением по адресу |
| Риск для продаж | Генератор делит память с базой и API. Ограничивается лимитом 1024 МБ и `oom_score_adj 500`: при нехватке памяти система убивает его первым | Никакого |
| Стоимость и работа | Ноль новых серверов, установка как на стенде | Новый сервер или перенос на `lead-parser`, где уже живут клиентские сайты |
| Отказ | Заявка уходит администратору, продажи не затронуты | То же, плюс зависимость от сети между серверами |

**Условие включения автогенерации на проде.** Ночью 13.11 ручная проверка стенда нашла дефект: черновик
генератора на экране проверки был залит чёрными кляксами. Причина: генератор писал SVG в единицах сетки
(холст 9 на 10) с обводкой места толщиной 3. Исправлено в генераторе: расстояние между местами 24, обводка
1, защита помечает непригодный рисунок и отдаёт заявку администратору. Пока исправленный образ генератора не
проверен глазами на стенде на настоящих файлах, **`VENUE_GEN_URL` и `VENUE_GEN_TOKEN` воркеру прода не
задавать**. Всё остальное выкатывается без генератора. Образ генератора для прода собирается из коммита с
исправлением, не раньше.

**Рекомендация: вариант А, но вторым шагом, не в ночь основного выката.** Основной выкат идёт с пустыми
`VENUE_GEN_URL` и `VENUE_GEN_TOKEN`: приём схем работает, каждую заявку берёт администратор, как на стенде до
волны 2. Генератор ставится отдельно, когда видно, что на `arena-prod` свободно не меньше 2 ГБ памяти при
обычной нагрузке. Если свободно меньше 2 ГБ, выбирать вариант Б или оставить генератор только на стенде.

Память прода агент не смотрел. Команда для владельца (только чтение):

```powershell
ssh arena-prod "free -m; docker stats --no-stream --format '{{.Name}} {{.MemUsage}}'"
```

Смотреть столбец `available` в строке `Mem`.
