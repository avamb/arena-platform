## 4. Настройка организации (на проде)

1. Payment configs → MyEventsArt → `flitt`, режим `live`. **Ключи вводит владелец.**
   Бейдж Connection должен стать `connected`.
2. Sales Channels → канал сайта организации: provider `flitt`.
3. Подключить сайт организации (виджет или страница промоутера).

## 5. Первый боевой платёж

Один платёж на минимальную сумму реальной картой, затем возврат в кабинете Flitt.
Проверить: callback 200 в логах, платёж `succeeded`, заказ `paid`, билет выдан, письмо
дошло, возврат покупателя через `payment-return` дал 303. В Telegram оператора не
должно быть алертов `payment_not_completed` и `manual_review`.

## 6. Откат

Вернуть тег `9b72a43` в пяти местах и Deploy. Миграция 0120 обратно совместима: старый
код не знает `flitt`, но строки не ломаются. Если на проде уже есть канал `flitt`,
перед откатом бэкенда переведите его на другого провайдера, иначе платёж на нём
не стартует. Откат схемы (`down-to 119`) переводит каналы `flitt` на `stripe`.

## 7. Известные ограничения

- Французский: письма, PDF-билет и страница Flitt поддерживают `fr`, но интерфейс
  виджета и страницы билетов остаётся английским. Чтобы покупатель получил `fr`,
  сайт организации задаёт `locale="fr"` у виджета; страница билетов пока выбирает
  язык только из `en/ru/cs/he/es`.
- Возврат из arena через API Flitt не вызывается — возврат делается в кабинете Flitt.
- Секрет `OPS_TELEGRAM_BOT_TOKEN` лежит в prod-compose открытым текстом, в отличие
  от остальных (`${...}`): вынести в Environment.
