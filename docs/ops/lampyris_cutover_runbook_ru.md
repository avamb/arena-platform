# Lampyris: переключение lampyrisevents.com с WordPress на сайт поверх платформы

Runbook по спеке 63, §10.2–10.4 и урокам У-1…У-20 (§4 спеки). Образец — переключение vinoandco.events 08.11.2026 (`docs/ops/vinoandco_cutover_runbook_2026-11_ru.md`). Инструменты: `ops/site-cutover/` (рендер маршрута, проба маршрута, конфиг `sites/lampyris.json`).

**Правило этого runbook.** Каждый шаг, который трогает прод, помечен:
- **[делает владелец]** — выполняет владелец сам (Deploy в Dokploy, панели Cloudflare, Stripe, Search Console, SQL на проде, ключи и токены);
- **[по явному слову владельца]** — агенты выполняют только после его слова в чате («переключаем», «выкатывай» и т. п.); сами по расписанию не запускают.

Расписание не запускает ни один шаг прода. T0 не раньше окончания тура Cory Henry (05.12) и только по слову владельца (спека 63, §10.5, В-13).

Адреса серверов, id Dokploy, токены и ключи в этом файле не пишутся. Адреса контейнеров обозначены `<…>`: их владелец читает через `docker ps` на сервере.

## 1. Подготовка до T0

Ветки, сборка и проверка идут агентами на стенде; прод не трогаем.

1. Выкат платформы на прод: [делает владелец] Deploy в Dokploy. После каждого нажатия проверить `deployment.allByType` (У-9); если деплой упал на clone, повторить (У-8).
2. Этапы 5–7 (перенос данных, приёмка, Николай) — по готовности, как в спеке §10.
3. Сайт на `new.lampyrisevents.com` собирается без падений, `/healthz` сборщика зелёный.
4. Шрифт Manrope с кириллицей и расширенной латиницей, глифы ů, ő, ą, ė, š, õ, є, ї проверены (У-10).
5. Мобильный аудит на 11 языках, 360 px: немецкий, финский и венгерский дают самые длинные слова (У-11).
6. Пересборка после нового образа: `SITE_BUILD_ID` в движке, баннер «Вышла новая версия» у ивент-центра (У-7, У-17). Николаю один раз Ctrl+Shift+R.
7. Статусы писем WP переносятся тем же импортом `arena-wp-letters-import` (У-18).

## 6. T0 — переключение маршрута [по явному слову владельца]

1. T0 выполняет владелец, агенты только дают команду. Файл `lampyris-site.yml` кладётся в `/etc/dokploy/traefik/dynamic/` сначала как `lampyris-site.yml.new`, затем переименовывается `mv` (как у Vino), чтобы Traefik не увидел наполовину записанный файл.
2. Traefik перечитывает файл сам. Проверка через 10 секунд: `curl -sI https://lampyrisevents.com/` отдаёт ответ нового сайта (`x-powered-by: PHP` и `server: Apache` при этом не приходят).
3. Labels WP в Dokploy не трогаем: их роутеры стоят на приоритете 25, файл маршрута выше (3000, 2000, 1500, 1000).

## 7. T0 + 1 час — проба маршрута и кеш

1. Пробы маршрута: GET и HEAD, без тела, по набору `ops/site-cutover/probes/lampyris.probes`. Прогон один раз, не в цикле [по явному слову владельца]. Скрипт `routing-check.sh` запускается из Git Bash (он написан под bash, на Windows PowerShell его не запускает): аргументы — файл проб, домен, публичный ip сервера, порт 443.
2. Ожидаем `N probes, 0 failed, 0 refused`. Проба Stripe webhook — только `-I`, живой POST не отправляется (У-19). Скрипт сам отклоняет любую пробу с телом или другим методом.
3. Второй сброс кеша Cloudflare после правок маршрута. [делает владелец]
4. Тестовая покупка на живом сайте в тестовом канале. Карту вводит человек (спека §11, п. 5). [делает владелец]
5. Search Console: sitemap 11 языков. [делает владелец]
6. Правила кеша Cloudflare как у Vino (две записи): всё, кроме WP-путей, колбэков и персональных страниц; страницы — 4 часа на краю, 404 — 5 минут, 5xx не кешируются; сброс изменённых страниц сборщиком. [делает владелец]

## 9. T2 — остановка WP [по явному слову владельца]

Условие T2 (спека §10.3): нет открытых заказов WC; нет `processing` без билетов; очередь возвратов пуста; все оплаты подтверждены по Stripe. Если до T0 ничего не изменилось, T2 — на следующий день после T0, когда сайт отработал сутки без замечаний.

1. Канал WP: `gateway.enabled=false`. [делает владелец]
2. Выключить подписчика `bil24_wp` этого канала. После этого платформа сама пишет покупателям и даёт переносить сеансы. [делает владелец]
3. Убрать роутеры WP из файла маршрута: заменить `lampyris-site.yml` на `lampyris-rollback.yml` тем же именем. Файл остаётся: после остановки WP его `certResolver` продлевает сертификат. [по явному слову владельца]
4. Владелец выключает старый webhook Stripe в кабинете Stripe. [делает владелец]
5. Остановить compose WP, тома хранить 4–6 недель. [делает владелец]
6. Убрать Lampyris из `wp-sites-backup.sh` после удаления томов. [делает владелец]
7. Пересмотреть правила Cloudflare против сканеров WordPress. [делает владелец]
8. MX и SPF не трогаем: почта домена живёт отдельно.

## 11. Чего не делаем

- Не публикуем тестовое мероприятие в канал WP (У-2, У-3).
- Не выполняем живой POST ни на один webhook (У-19).
- Не запускаем шаги прода по расписанию (У-20).
- Не вставляем адреса серверов, id Dokploy и токены в репозиторий, чат или отчёты.
- Не копируем ключи и пароли из `arena-site-secrets`, `AVA_Agents` и `.env`-файлов.
