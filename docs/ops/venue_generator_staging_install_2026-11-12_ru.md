## Выбранный лимит

Лимит контейнера: 1024 МБ. Это вдвое больше пика на настоящих файлах и ниже потолка 1,5 ГБ.

Все три адаптера включены: XLSX, PDF, изображение.

Ограничение: изображение больше примерно 40 мегапикселей в лимит не укладывается.
Ядро убивает дочерний процесс заявки, заявка получает `failed` с кодом `worker_crashed`.
Сам сервис и соседние контейнеры это не затрагивает.
В корпусе таких изображений нет.

`VENUE_GEN_JOB_MEMORY_MB` оставлен 2048.
Эта настройка ограничивает виртуальную память процесса заявки, а не занятую.
При значении 900 настоящие PDF с пиком 250 МБ завершались ошибкой `memory_limit`.
Настоящую память ограничивает лимит контейнера.

## Откат

Откат убирает только генератор. Стенд после него работает, как до установки.

1. Удалить контейнер: `docker rm -f arena-venue-generator`
2. Удалить образ: `docker image rm arena-venue-gen:sync-8373cc40`
3. Удалить каталог с токеном и скриптами: `rm -rf /opt/arena-venue-gen`

Для временной остановки хватит `docker stop arena-venue-generator`. После неё контейнер сам не поднимется, пока его не запустят.

## Обновление образа

1. Собрать локально: `docker build --build-arg VENUE_GEN_COMMIT=<sha> -t arena-venue-gen:<метка> apps/venue-svg-generator`
2. Передать: `docker save arena-venue-gen:<метка> | gzip -1 | ssh lead-parser "gunzip | docker load"`
3. На сервере: `/opt/arena-venue-gen/run.sh arena-venue-gen:<метка>`

На сервере образ не собирать: сборка ставит numpy и opencv и нагружает память рядом с боевыми сайтами.

## Что нужно помнить

- Контейнер подключён к сети стека стенда. Команда `docker compose down` для стека не сможет удалить сеть, пока генератор работает. Обычный деплой Dokploy (`up -d`) сеть не трогает.
- Если сеть стенда пересоздали, запустить `/opt/arena-venue-gen/run.sh` ещё раз.
- Остановленный стек `arena-wordpress-hpl1ba` не запускать и не удалять.
