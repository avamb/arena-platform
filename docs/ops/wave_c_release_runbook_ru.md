# Выкат волны C: порядок по шагам

Дата: 23.10.2026. Время везде по Мадриду.

**Результат.** Выкатывать нужно в строгом порядке: сначала бэкап, потом образ и миграции, потом API с воркером, потом бот, потом веб. Любой другой порядок даёт ошибки у людей или ломает миграции. Шаги ниже выполняются сверху вниз, каждый шаг имеет проверку. Не переходите к следующему шагу, пока проверка предыдущего не прошла.

Что входит в выкат: интеграционный PR «Wave C release batch» (десять задач: права на раскладку мест, пакеты мест с откатом, подбор раскладки, места в пакете мероприятия, HTTP генератора схем, юридические документы, метка VIP, текст организатора в письме, статистика страницы, показ входов).

## Что нужно знать до начала

1. Пять новых миграций идут подряд: 0161, 0162, 0163, 0164, 0165. Все только добавляют. Откат кода без отката базы безопасен: старый образ работает с новой схемой.
2. Голова миграций на master перед выкатом: 0157 (биллинг). Другие открытые PR биллинга и промо занимают 0158, 0159, 0160. **Если они попадут в master после нашего выката, их миграции станут «пропущенными», и обычный запуск миграций откажется их применять.** Перед вливанием договоритесь с сессией биллинга: либо они перенумеруются выше 0165, либо выкатываются раньше нас.
3. Генератор схем (G2a) в прод не выкатывается. У него нет порта и отдельного приложения Dokploy.
4. Новые переменные окружения необязательны: `PUBLIC_PAGE_TRACK_EVENT_RATE_LIMIT` (по умолчанию 6000 в минуту) и `PUBLIC_PAGE_TRACK_IP_RATE_LIMIT` (по умолчанию 120 в минуту). Если не задавать, работают значения по умолчанию.
5. Сервис `arena-worker` и `arena-api` должны быть одного образа. Старый воркер завершит задание письма-теста ошибкой «no handler».

## Шаг 0. Перед началом

Предупреждение: миграции нельзя откатить без восстановления базы из дампа. Дамп нужен свежий.

1. Убедитесь, что интеграционный PR зелёный по всем проверкам и слит в master владельцем.
2. Убедитесь, что на master прошёл CI и опубликован образ. Проверка образа без `gh`: запрос манифеста `ghcr.io/avamb/arena-api:<короткий sha>` должен вернуть 200, а не 404 (подробности в заметке о механике выката 20.09).
3. Сделайте внеплановый дамп базы на сервере Arena по `docs/ops/backup_and_restore_runbook_2026-10-02_ru.md`. Запомните имя файла.
4. Запишите текущий коммит прода (строка `APP_COMMIT` и тег образа в compose `backend-prod`). Он нужен для отката.

## Шаг 1. Бэкенд: образ и миграции

1. В Dokploy откройте compose `backend-prod`.
2. Замените тег образа `ghcr.io/avamb/arena-api:<sha>` во всех трёх сервисах (api, worker, migrate) на новый короткий sha. Замените также `APP_COMMIT` в блоке `x-arena-env`. Всего четыре строки.
3. Нажмите Deploy.
4. Проверка: контейнер `migrate-1` завершился с кодом 0 (`Exited (0)`), api и worker запущены на новом образе.
5. Проверка по поведению: запрос без токена на новый маршрут, например `GET /v1/organizations/{org_id}/sessions/{session_id}/seat-batches`, отвечает 401. Несуществующий маршрут отвечает 404. Если новый маршрут отвечает 404, образ старый: повторите Deploy.
6. Проверка базы: в таблице `schema_migrations` последняя применённая версия 0165.

Если шаг не прошёл: верните старые четыре строки (тег и `APP_COMMIT`) и нажмите Deploy. Базу не откатывайте.

## Шаг 2. Права: проверить, что владелец и менеджер не потеряли доступ

Миграция 0161 выдаёт новое право `session.seats.manage` владельцу, менеджеру и суперадмину. Проверка: войдите менеджером в веб-ивент-центр и откройте схему зала сеанса. Кнопки блокировки и раскраски мест должны быть доступны. Агент их не видит.

## Шаг 3. Бот

Бот работает на том же образе (сервис `bot`).

1. Убедитесь, что сервис `bot` в compose указывает на новый тег. Если он вынесен отдельно, поменяйте тег и там.
2. Нажмите Deploy сервиса `bot`.
3. Проверка: в боте откройте карточку заказа. Должны быть строки со сканами входа (если они были) и значок VIP у билета. На карточке сеанса есть кнопка «Не прошли».
4. После перезапуска старые экраны в чате устаревают. Это нормально: нажмите «☰ Меню».

## Шаг 4. Веб-ивент-центр

1. В Dokploy откройте приложение `event-center` (`rrmdt_kDJwyjR_LrxnDIU`) и нажмите Deploy. Образ собирается из master.
2. Проверка: страница открывается по адресу `https://events.arenasoldout.com`. Запросите бандл с `?cb=<случайное число>`, чтобы обойти кэш Cloudflare, и убедитесь, что в нём есть новые экраны (например `scans` или `vip`).
3. Проверка руками: карточка заказа показывает метку VIP, на экране мероприятия есть блок статистики страницы.

## Шаг 5. Страница покупателя (tickets-page)

Выкатывайте только после шага 1. До этого маяк статистики получает 404 и ничего не ломает, но данных не будет.

1. Откройте приложение `tickets-page` (`im4UbEuMLUMpTycbAMLeS`) и нажмите Deploy.
2. Проверка: откройте страницу мероприятия, запустите видео или нажмите партнёрскую ссылку. В ответах сети виден запрос `/track` со статусом 204.

## Шаг 6. Итоговая проверка

1. Продажа: сделайте тестовую покупку на странице ABH TEAM (Stripe test). Билет приходит письмом, блок «О мероприятии» есть, если вы его заполнили.
2. Приглашение: выдайте приглашение с отметкой VIP. Билет приходит без слова VIP в письме и в PDF (это правило).
3. Условия продажи: страница условий отвечает 404 `terms.not_published`, пока юрист не утвердил текст. Это ожидаемо, согласие остаётся на условиях платформы.
4. Журналы: в Dokploy откройте логи api и worker за первые 15 минут. Не должно быть повторяющихся ошибок.

## Откат

1. Верните в compose старый тег образа и старый `APP_COMMIT`, нажмите Deploy. Веб и бот откатываются тем же образом/Deploy предыдущей сборки.
2. Базу оставьте как есть. Новые таблицы и колонки старому коду не мешают.
3. Если ломается именно миграция (контейнер `migrate-1` завершился не нулём): ничего не делайте с базой руками, напишите разработчику. Дамп из шага 0 остаётся последней страховкой.

## Что не проверено заранее

1. Накатка пяти миграций на копию боевой базы с данными. Проверена накатка на чистую базу и на базу с миграциями до 0157.
2. Отправка писем и PDF через настоящий почтовый сервис.
3. Нагрузка на новые маршруты (маяк статистики, список пакетов мест).
