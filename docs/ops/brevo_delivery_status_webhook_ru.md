# Статус писем покупателям: вебхук Brevo

Организатор видит, дошло ли письмо покупателю: «в очереди», «отправлено»,
«задерживается», «доставлено», «открыто» или «не доставлено» с причиной.
Статус приходит от Brevo через вебхук транзакционных писем. Без настройки
вебхука организатор видит только «отправлено».

Arena записывает все письма покупателю: письмо с билетами, приглашение,
перенос и отмена сеанса, возврат. Карточка заказа показывает письма с
билетами, письма о переносе и отмене и письма о возврате. Приглашение не
привязано к заказу, поэтому его статус пока нигде не показывается. Оно
хранится в базе как доказательство (раздел 4).

## 1. Что нужно сделать владельцу

Порядок важен: сначала токен на сервере, потом вебхук в Brevo.

### 1.1. Создать токен

1. Откройте PowerShell на своём компьютере.
2. Выполните команду. Она печатает случайную строку из 64 символов.

```powershell
$b = New-Object byte[] 32; [System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); -join ($b | ForEach-Object { $_.ToString('x2') })
```

3. Сохраните строку в менеджере паролей. Это секрет: кто знает токен, тот
   может менять статусы писем.

### 1.2. Передать токен arena-api

1. Откройте панель Dokploy, проект Arena на сервере arena-prod.
2. В переменных окружения сервиса arena-api добавьте строку
   `BREVO_WEBHOOK_TOKEN=<ваш токен>`.
3. Перезапустите (Deploy) arena-api.

Без этой переменной адреса вебхука не существуют: сервер отвечает 404.
В продакшене токен короче 32 символов не принимается, и сервер не
запустится. Поэтому используйте команду из шага 1.1.

### 1.3. Проверить адрес до настройки Brevo

Выполните команду, подставив токен:

```powershell
Invoke-RestMethod -Method Post -Uri "https://api.arenasoldout.com/v1/webhooks/brevo" -Headers @{ Authorization = "Bearer <ваш токен>" } -ContentType "application/json" -Body '{"event":"delivered","message-id":"<check@example.com>"}'
```

Ожидаемый ответ: `acknowledged: True`, `received: 1`, `applied: 0`.
`applied: 0` правильно: такого письма Arena не отправляла.

Если пришёл ответ 401, токен в команде не совпадает с токеном на сервере.
Если пришёл ответ 404, переменная не дошла до arena-api: проверьте шаг 1.2.

### 1.4. Добавить вебхук в Brevo (рекомендуемый способ: через API)

Внимание: аккаунт Brevo общий с сайтами WordPress. Не меняйте и не удаляйте
существующие вебхуки (например, вебхук Lampyris). Добавьте новый вебхук рядом.

При этом способе токен передаётся в заголовке `Authorization`, а не в
адресе. Поэтому он не попадает в журналы доступа Traefik и Cloudflare.
Форма Brevo в браузере заголовок задать не позволяет. Это умеет только
API Brevo.

1. В Brevo откройте «SMTP & API» → «API Keys» и создайте ключ API. Сохраните
   его в менеджере паролей.
2. Выполните команду, подставив ключ API и токен из шага 1.1:

```powershell
Invoke-RestMethod -Method Post -Uri "https://api.brevo.com/v3/webhooks" -Headers @{ "api-key" = "<ключ API Brevo>" } -ContentType "application/json" -Body '{"type":"transactional","description":"Arena letter status","url":"https://api.arenasoldout.com/v1/webhooks/brevo","auth":{"type":"bearer","token":"<ваш токен>"},"events":["request","delivered","opened","uniqueOpened","proxyOpen","click","deferred","hardBounce","softBounce","blocked","invalid"]}'
```

3. Ожидаемый ответ: `id` нового вебхука. Сохраните его рядом с токеном.
4. Если Brevo отказал из-за названия события, уберите это событие из списка
   и повторите. Arena понимает все известные написания событий.

### 1.4a. Запасной способ: форма Brevo

Используйте его, только если способ 1.4 не сработал. Токен тогда стоит в
адресе. Arena вырезает его из своих журналов, но Traefik и Cloudflare могут
записать адрес целиком в свои журналы доступа.

1. Войдите в Brevo.
2. Откройте «Transactional» → «Settings» → «Webhook».
3. Нажмите «Add a new webhook».
4. В поле URL введите
   `https://api.arenasoldout.com/v1/webhooks/brevo/<ваш токен>`.
5. Отметьте события: Sent (в API называется request), Delivered, Opened,
   First opening, Loaded by proxy (если есть в списке), Clicked, Deferred,
   Hard bounce, Soft bounce, Blocked, Invalid email, Error (если есть).
6. Не отмечайте Unsubscribed, Spam, Complaint. Arena их не использует. Если
   они всё же придут, Arena ответит 200 и пропустит их.
7. Сохраните вебхук.

### 1.5. Проверить на живом письме

1. Купите тестовый билет на тестовом мероприятии на свой адрес.
2. Через 1–2 минуты откройте заказ в боте или в ивент-центре.
3. Письмо с билетами должно показать «доставлено», а после открытия письма
   «открыто». Бот читает статусы из `letters[]` карточки заказа с
   октября 2026 года. Если бот показывает только «отправлено», значит,
   вебхук не работает: проверьте шаги 1.2–1.4.

### 1.6. Сменить токен без потери событий

1. Создайте новый токен (шаг 1.1).
2. В Dokploy перенесите старый токен в `BREVO_WEBHOOK_TOKEN_PREVIOUS`, а
   новый запишите в `BREVO_WEBHOOK_TOKEN`. Перезапустите arena-api. Теперь
   сервер принимает оба токена.
3. Поменяйте токен в вебхуке Brevo. Для вебхука из шага 1.4 это запрос
   `PUT https://api.brevo.com/v3/webhooks/<id вебхука>` с новым `auth`. Для
   вебхука из формы поменяйте адрес.
4. Через сутки удалите `BREVO_WEBHOOK_TOKEN_PREVIOUS` и перезапустите
   arena-api.

## 2. Как это устроено

- arena-worker отправляет письма через SMTP-релей Brevo. Перед отправкой
  он записывает письмо в таблицу `email_letters` и ставит в письмо заголовок
  `X-Mailin-custom: arena-letter:<id письма>`. Brevo возвращает этот заголовок
  в каждом событии вебхука.
- Релей Brevo принимает письмо ответом `250 ... queued as <id>`. Arena
  сохраняет этот id как `provider_message_id`. Событие вебхука Arena находит
  по заголовку или по этому id. Если релей вернул id, который уже есть у
  другого письма, письмо всё равно становится «отправлено» и связывается со
  своими билетами. Id тогда остаётся только у первого письма.
- Все строки `delivery_jobs` одного письма с билетами ссылаются на одну
  строку `email_letters` (`email_letter_id`).
- Каждое событие хранится один раз на письмо и тип события
  (`email_letter_events`) с первым и последним временем. Статус письма
  пересчитывается по всему набору событий. Повтор события и событие, которое
  пришло не по порядку, не портят статус.
- Порядок статусов: отправлено < задерживается < доставлено < открыто.
  Ошибка доставки окончательна, если после неё не пришла более поздняя
  доставка. Так «soft bounce», который Brevo потом доставил, становится
  «доставлено».
- «Задерживается» (deferred): сервер получателя попросил Brevo повторить
  позже. Brevo повторяет сам. Время первой задержки хранится в
  `deferred_at` и остаётся после доставки.
- События писем, которые Arena не отправляла (письма сайтов WordPress в
  том же аккаунте), Arena принимает с ответом 200 и не сохраняет.
- Тело запроса ограничено 1 МиБ. Число событий в пачке не ограничено,
  поэтому большая пачка не отклоняется.
- В событиях не хранится адрес покупателя. Из причины ошибки удаляются
  адреса почты, IP-адреса и имена серверов получателя. Остаются код SMTP и
  текст («550 5.1.1 user unknown»).
- Каждое открытие, загрузка через прокси и клик хранятся отдельной строкой
  со своим временем (`email_letter_interactions`). У клика хранится только
  адрес сайта и путь ссылки. Параметры ссылки и длинные токены в пути (в том
  числе токены из частей через точку, например JWT) заменяются на `{token}`.
- Клик считается доказательством доставки, но не прочтения: почтовые
  сканеры безопасности тоже открывают ссылки.

## 3. Важно про «открыто»

Brevo узнаёт об открытии, когда почтовая программа загружает картинки
письма. Почта Apple (защита конфиденциальности, Mail Privacy Protection)
загружает картинки сразу при доставке, даже если человек письмо не читал.
Brevo сообщает такие загрузки отдельным событием (loaded by proxy). Arena
считает его доказательством доставки, а не прочтения: поле
`proxy_opened_at`, статус «доставлено».

Даже обычное «открыто» не гарантирует, что человек прочитал письмо.
Некоторые почтовые программы загружают картинки сами. Показывайте
«открыто» как подсказку, а не как факт.

## 4. Письмо как доказательство при оспаривании платежа

Покупатель может оспорить платёж картой и сказать, что билетов не получил.
Поэтому у каждого отправленного письма Arena хранит:

- точный адрес получателя;
- адрес отправителя (From) и адрес для ответа (Reply-To), если он был;
- тему письма;
- номера билетов в письме;
- id сообщения у Brevo;
- хеш SHA-256 текста письма (сам текст не хранится);
- имена, размеры и хеши SHA-256 приложенных PDF-билетов;
- версию шаблона письма: имя файла и начало его хеша.

По этим данным можно доказать, какое письмо ушло, даже после изменения
шаблонов.

Письмо, которое осталось в состоянии `sending` больше суток, проверяется
перед отправкой следующего письма (проверка идёт при каждой отправке,
порог — сутки; если писем нет, проверка не идёт). Правила:

- Письмо становится «отправлено» с отметкой `receipt_missing` (нет id
  сообщения), если его СОБСТВЕННЫЙ источник говорит, что письмо ушло:
  задание доставки этого письма, уведомление о переносе или отмене,
  связанное с этим письмом, или возвраты, связанные с этим письмом.
  Уведомление или возврат того же заказа, связанные с другим письмом,
  ничего не доказывают: при повторной отправке связь переходит к новому
  письму.
- Письмо, у которого задание доставки осталось `processing`, не
  удаляется: отправщик мог упасть после ответа релея, письмо могло уйти.
  Оно остаётся в `sending` и в карточке заказа не показывается.
- Остальные письма удаляются: их никто не подтвердил.
- При включённом вебхуке событие Brevo по заголовку `X-Mailin-custom`
  тоже переводит такое письмо в «отправлено» и дальше. При выключенном
  вебхуке остаются только правила выше.

## 5. Срок хранения и правовое основание

**Нижняя граница: 24 месяца.** Письма, их события, открытия и клики
хранятся не меньше 24 месяцев. Оспорить платёж картой можно в течение
120–540 дней, а разбор спора идёт ещё несколько месяцев. Ни одна задача
очистки не удаляет эти данные раньше. Это проверяет тест
`tests/staticanalysis/email_letters_retention_test.go`.

**Срок считается от даты мероприятия** (решение владельца 14.10.2026).
Билет можно купить за 12–18 месяцев до мероприятия и оспорить до 120 дней
после него. Срок от даты письма закончился бы раньше спора. Поэтому:

- Письмо, привязанное к сеансу, хранится от `max(время отправки, конец
  сеанса)`. Сеанс письма находится по его заказу, по уведомлению о переносе
  или отмене и по номерам билетов в паспорте письма (у приглашения заказа
  нет).
- Письмо без сеанса хранится от времени отправки.
- Если у письма несколько сеансов, берётся самый поздний конец.

Правило записано в коде один раз: `emailstatus.RetentionAnchorSQL` и
`emailstatus.RetentionStart`. Тест
`delivery/letter_retention_integration_test.go` проверяет каждый путь к
сеансу.

**Верхняя граница: 36 месяцев** от того же начала отсчёта. Дольше эти данные
хранить не нужно. Задачи очистки пока нет. Таблица начала заполняться в
октябре 2026 года, поэтому первая запись достигнет 36 месяцев не раньше
октября 2029 года. Очистку нужно добавить до этого срока. Она должна
считать срок от `emailstatus.RetentionAnchorSQL`, а не от `sent_at`. Она
удаляет записи старше 36 месяцев и оставляет 24 месяца. Её добавляют в тест
и в этот документ в одном коммите.

**Правовое основание (GDPR).** Статья 6(1)(f): законный интерес продавца
защищаться от оспаривания платежа и подтверждать доставку билетов. Объём
данных минимальный: нет текста письма, нет IP-адреса и браузера читателя,
нет параметров ссылок. Запрос покупателя на удаление может быть отклонён
для этих записей по статье 17(3)(e), пока срок спора не истёк: данные нужны
для защиты от правового требования. Текст для политики конфиденциальности
должен согласовать юрист владельца.

Удаляется сразу только письмо, которое релей не принял (статус `sending`):
его никто не получил, доказывать нечего.

Удаление организации удаляет и её письма. Организации на проде не
удаляются, а архивируются.

## 6. Что Arena НЕ хранит

Время события Arena берёт из `ts_epoch` (или `ts_event`, `ts`). Поле
`date` Brevo пишет в местном времени аккаунта без пояса, поэтому Arena
его использует, только если в нём указан пояс. Иначе событие получает
время приёма.

Arena не хранит IP-адрес и браузер (user agent) того, кто открыл письмо или
нажал ссылку. Даже если Brevo их присылает, Arena их не сохраняет. Решение
о том, хранить ли их как доказательство при оспаривании платежа, за
владельцем: это персональные данные покупателя, и нужна оценка законного
интереса.

## 7. Что читают бот и веб-ивент-центр

- Карточка заказа `GET /v1/organizations/{org_id}/orders/{id}`:
  - `letters[]` — письма заказа: `kind` (ticket, change, cancel, refund),
    `status` (queued, sent, delayed, delivered, opened, failed),
    `recipient`, `ticket_ids`, `queued_at`, `sent_at`, `delivered_at`,
    `proxy_opened_at`, `opened_at`, `clicked_at`, `deferred_at`,
    `failed_at`, `failure_event`, `failure_reason`, `stuck`;
  - `letter_failed` — у заказа есть письмо, которое не дошло (`failed`) или
    зависло (`stuck`).
- `stuck`: письмо больше 6 часов в состоянии «отправлено» или
  «задерживается» и не доставлено, хотя вебхук за это время присылал
  события. Покупатель, скорее всего, письма не получил. Если вебхук вообще
  молчит (выключен), письмо не считается зависшим.
- Список заказов `GET /v1/organizations/{org_id}/orders`: у каждого заказа
  `letter_failed` по тому же правилу.
- Описание полей: схема `OrderLetter` в `apps/backend/openapi/openapi.yaml`.

## 8. Наблюдение и сбои

- Метрики: `arena_email_webhook_events_total{event_type,outcome}` и
  `arena_email_webhook_rejected_total{reason}`. `outcome=not_ours` — это
  нормально (письма сайтов). Постоянный рост `reason=bad_token` значит, что
  кто-то перебирает токен.
- Если Arena не смогла сохранить событие, она отвечает 500. Brevo пришлёт
  событие ещё раз.
- Brevo отключает вебхук, который долго отвечает ошибками. Если статусы
  перестали обновляться, откройте вебхук в Brevo и проверьте, что он включён.
- Письма, отправленные до включения этой функции, показываются как
  «отправлено» без дальнейших шагов.

## 9. Что не проверено

- Ответ живого релея Brevo `queued as <id>` и совпадение этого id с полем
  `message-id` в событиях проверены только на тестовом SMTP-сервере. Если id
  не совпадёт, Arena всё равно найдёт письмо по заголовку `X-Mailin-custom`.
  После первой живой покупки проверьте в базе, что у письма заполнен
  `provider_message_id` и есть строки в `email_letter_events`.
- Запрос создания вебхука через API Brevo (шаг 1.4) и названия событий в
  нём взяты из документации Brevo. На живом аккаунте они не выполнялись.
- Названия событий в форме Brevo могут отличаться от списка в шаге 1.4a.
  Arena понимает все известные написания (request, unique_opened,
  loaded_by_proxy и другие).

## 10. Отписка в транзакционных письмах

Найдено 2026-10-15: владелец увидел «Unsubscribe» в письмах с билетами.

**Откуда он берётся.** Не из Arena. В шаблонах (`delivery/templates`, 49 файлов,
7 языков) и в сборке письма (`adapters/email/sender.go`) нет ни ссылки, ни
заголовка `List-Unsubscribe`. Его добавляет сам релей Brevo. Справка Brevo
говорит, что релей автоматически включает заголовок list-unsubscribe в
рассылки и в транзакционные письма
(https://help.brevo.com/hc/en-us/articles/19100260472850, страница отдала
403, текст взят из выдачи поиска). Представитель Brevo ответил в сообществе
10.06.2024: «Brevo automatically adds a list-unsubscribe header», его можно
заменить заголовком list-help, но только на тарифе Enterprise
(https://community.brevo.com/t/header-of-transactional-emails-with-no-unsubscribe-links-are-wrongly-still-unsubscribable/1251).
Почтовые клиенты (Gmail, Apple Mail) показывают этот заголовок как кнопку
«Отписаться» рядом с отправителем. Нажатие заносит адрес в список
заблокированных транзакционных контактов Brevo, и дальше Brevo не доставляет
этому адресу ничего: ни билеты, ни письма о возврате.

**Что делает Arena.** Заголовок `List-Unsubscribe` не пишется, слов «отписаться»
в письмах нет. Это закреплено тестами
`TestBuildMIMEMessage_NoListUnsubscribeHeader` и
`TestTransactionalTemplates_*NoUnsubscribe`. Свой `List-Unsubscribe` Arena
добавлять не будет: документации о том, что Brevo уважает такой заголовок от
отправителя по SMTP, нет, а подмена ссылкой Arena не защищает от блокировки.

**Что не проверено.** Мы не видели сырое письмо с живого релея и не знаем
точно, какой элемент видел владелец: заголовок (кнопка в Gmail) или нижняя
строка, которую вставляет Brevo. Шаг 1 это выясняет.

### Что сделать владельцу

Все времена в тексте письма в Brevo и в журналах — по Мадриду.

1. Откройте любое письмо с билетами в Gmail, нажмите три точки, затем
   «Показать оригинал» (Show original). Найдите строки `List-Unsubscribe:` и
   `List-Unsubscribe-Post:`. Если они есть, источник — релей Brevo. Пришлите
   сырое письмо без вложений, это закроет пробел «не проверено».
2. Напишите в поддержку Brevo (раздел Help, «Contact support»). Текст на
   английском:

   > Our SMTP relay account sends only transactional mail: tickets, order
   > confirmations, refunds, triggered by the recipient's own purchase. It
   > contains no promotional content. Please replace the List-Unsubscribe
   > header with a List-Help header on our account, as described for
   > Enterprise plans, or tell us which plan we need. A recipient who presses
   > Unsubscribe is now blocked for all later transactional mail.

   Ответ на тарифе ниже Enterprise, скорее всего, будет «только Enterprise».
   Тогда решение — отдельный транзакционный провайдер или отдельный
   аккаунт Brevo под билеты. Это решение владельца.
3. Не включайте в Brevo автоматизацию «Email - Unsubscribed from emails →
   Blocklist contact → all emails»: она расширяет блокировку на все каналы.
4. Проверьте, кто уже отписался. В Brevo: Settings → Transactional → Blocked
   or Unsubscribed contacts. Либо запросом (ключ API хранится в переменной
   окружения, в команду его вписывать не нужно):

   ```powershell
   $env:BREVO_API_KEY = Read-Host "Brevo API key"
   ```

   ```powershell
   Invoke-RestMethod -Uri "https://api.brevo.com/v3/smtp/blockedContacts?limit=100" -Headers @{ "api-key" = $env:BREVO_API_KEY }
   ```

5. Разблокировать можно только того, кто отписался по ошибке (нажал кнопку в
   Gmail, а не потребовал прекратить письма). Brevo предупреждает, что
   разблокировка человека, который просил прекратить рассылку, незаконна.
   Запрос (почту подставьте в адрес):

   ```powershell
   Invoke-RestMethod -Method Delete -Uri "https://api.brevo.com/v3/smtp/blockedContacts/buyer%40example.com" -Headers @{ "api-key" = $env:BREVO_API_KEY }
   ```

   Ответ 204 значит «разблокирован», 404 — «в списке нет».
6. После ответа поддержки напишите об этом в чат: Arena ничего менять не
   нужно, но этот раздел надо обновить.
