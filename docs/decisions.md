Общий журнал для Андрея и Марины. Новые записи сверху. Формат: дата, решение, причина, где закреплено.

Это входная точка. Здесь только самые значимые решения владельца, по одной записи, со ссылкой на источник. Полные формулировки и мелкие решения лежат там же, где записаны: `docs/agents/*.md`, `docs/backlog_ru.md`, спеки в `08_architecture/`. ## 2026-11-25 (владелец): место за покупателем с момента клика по схеме
**Решение:** на сеансе со схемой зала место закрепляется в момент клика. «Место занято» бывает только в момент клика, дальше место не отнимается. Сроки: 10 минут до окна заказа, затем 15 минут на e-mail и оплату, одно продление на 5 минут на всю бронь. Пока идёт оплата, бронь не снимается. Сессию Stripe закрываем сами. Лимиты против ботов: 10 мест в брони, 2 открытые брони на устройство и до 6 на адрес, пауза 5 минут на повтор тех же мест. Сроки меняет суперадмин, режим «высокий спрос» (7 и 10 минут) тоже включает суперадмин. Без проверенного адреса покупателя за Cloudflare бронь по клику на прод не выходит.
**Причина:** прогон 24.11 на стенде: 744 из 922 покупателей быстрого пути и 368 из 375 обычного получили «место занято» уже после выбора. Брошенные брони держали зал 33 минуты. Покупатель не должен жаловаться организатору.
**Закреплено:** `08_architecture/67_seat_hold_on_click_ru.md` (§0, §13).

## 2026-11-22 (Андрей): подключение Meta (М1) — шифрованный токен, только владелец, вход через редирект
**Решение:** токен Meta шифруется в БД (AES-GCM, ключ `META_TOKEN_ENC_KEY`, версия ключа в значении). Без ключа или без `META_APP_ID` функция выключена. Подключает только владелец (`org.update`), ключ API организации отклоняется. Пилот — ABH TEAM на стенде. Ручной токен CAPI остаётся запасным путём. Вход — серверный редирект `dialog/oauth` с `config_id`, без JS SDK Meta в ивент-центре.
**Причина:** бессрочный токен BISU даёт доступ к чужим рекламным кабинетам. Для JS SDK пришлось бы ослабить CSP и COOP всего ивент-центра, а refresh-токен лежит в localStorage. Редирект с `config_id` описан в документации Meta.
**Закреплено:** `08_architecture/66_meta_ads_integration_ru.md` §4, §4.1а, §9; `docs/agents/meta-integration.md`.
## 2026-11-22 (владелец): переводы содержимого мероприятия правит организатор, машинный перевод ручной текст не трогает
**Решение:** организатор задаёт свой текст перевода для любого мероприятия: название (если отличается), краткое и полное описание, текст фотоотчёта. Ручной текст получает `source='manual'` и машинным переводом не перезаписывается никогда, флага перезаписи нет. Чтобы заменить ручной текст машинным, перевод сначала удаляют. При изменении оригинала ручной перевод остаётся и помечается «устарел».
**Причина:** переводы Lampyris оплачены и выверены людьми; машинный перевод — только заготовка для языков без перевода.
**Закреплено:** спека 63 §16 (редакция 4), `docs/agents/public-pages-widget.md`. Поле `name` в переводе добавлено по требованию 22.11, хотя §16.1 спеки его ещё не называет.

## Решения владельца, собранные из репозитория

### 2026-11-12: в письмах бренд пишется только ArenaSoldOut.com
**Решение:** ни «Arena», ни «Arena Platform», ни «Arena Sold Out», на всех семи языках (иврит оставляет латиницу).
**Причина:** один узнаваемый бренд в письмах покупателям, никаких вариантов написания.
**Закреплено:** `docs/agents/delivery-email-pdf.md` (тест `apps/backend/internal/platform/delivery/brand_guard_test.go`).

### 2026-11-12: меню веб-ивент-центра повторяет разделы меню бота
**Решение:** одна модель (`apps/event-center/src/lib/navMenu.ts`) решает, какие разделы видит человек, и для бота, и для веба.
**Причина:** организатор переходит между ботом и вебом и находит одно и то же на тех же местах. (вывод автора журнала, источник причину прямо не называет)
**Закреплено:** `docs/agents/web-event-center-screens.md`.

### 2026-11-08: перевыпуск билета не меняет покупателя заказа, импорт старых билетов Bil24 ничего не рассылает
**Решение:** перевыпуск на другой e-mail ставит `buyer_email`, но не трогает `orders.customer_id` (отдельная задача Р-21). Импорт билетов, проданных в Bil24 до платформы, не пишет событий, писем, вебхуков и расхода биллинга.
**Причина:** перенос сайта клиента: покупатели старых билетов не должны получить ни одного письма, штрихкоды MACS знает со времён Bil24.
**Закреплено:** `docs/agents/orders-invitations-scans.md`, `08_architecture/63_ticket_reissue_wrong_recipient_ru.md`.

### 2026-11-07: 224 оплаченных заказа магазина, которые Shopify не отметил выполненными, хранятся как отправленные
**Решение:** при импорте они получают статус «отправлен» на момент оплаты (`metadata.shipped_assumed`), возвращённые не трогаем.
**Причина:** без этого очередь «к отправке» заполнилась бы старыми заказами, которые давно у покупателей. (вывод автора журнала, источник причину прямо не называет)
**Закреплено:** `docs/agents/shop.md`.

### 2026-11-05: магазин после окончания платного периода остаётся доступен для заказов навсегда
**Решение:** если у организации есть оплаченный или открытый заказ магазина, список, карточка, отправка и возврат остаются доступны (режим `orders_only`).
**Причина:** деньги и заказы покупателей нельзя закрыть вместе с модулем. (вывод автора журнала, источник причину прямо не называет)
**Закреплено:** `docs/agents/shop.md`.

### 2026-11-03: людям список гостей отдаётся в Excel, CSV остаётся для импорта
**Решение:** гостевой список для людей в виде Excel-файла.
**Причина:** Excel открывает CSV с разделителем из региональных настроек, при английских настройках каждая строка падает в одну колонку.
**Закреплено:** `docs/agents/orders-invitations-scans.md`.

### 2026-11-03: процент «Приведи друга» считается с суммы товаров после скидки, кэшбэк не является возвратом
**Решение:** база процента: билеты или товары друга после скидки, без сервисного сбора, доставки, комиссии и налога. Кэшбэк реферера отражается в отчётах продаж отдельно от возвратов покупателю.
**Причина:** кэшбэк возвращается из денег самого реферера, а не покупателю, и не должен превращаться в обычный возврат.
**Закреплено:** `docs/agents/referral.md`, `08_architecture/52_refer_a_friend_ru.md`.

### 2026-11-02: минуты GitHub Actions берегём, проверяем локально и пушим один раз за этап
**Решение:** полный прогон CI делаем на своей машине, на GitHub отправляем законченный этап, не «посмотреть CI».
**Причина:** репозиторий на бесплатном плане (2000 минут в месяц), один полный прогон около 85 минут, 2 ноября частые пуши исчерпали месяц и все задачи встали.
**Закреплено:** `AGENTS.md` (раздел CI jobs).

### 2026-11-02: список гостей сеанса, автоматическая отправка только по согласию, в личный чат

**Причина:** в списке персональные данные гостей, поэтому ничего не уходит в общие чаты без явного согласия. (вывод автора журнала, источник причину прямо не называет)
**Закреплено:** `docs/agents/orders-invitations-scans.md` (миграция 0187).

### 2026-11-02: «Умная цена» — набор настроек для мастера, а не второй движок цен

**Причина:** один движок цен на платформе, без расхождений между кассой, виджетом и шлюзом. (вывод автора журнала, источник причину прямо не называет)

## 2026-11-22. Согласие на отслеживание сайта Lampyris: «включено, пока не отказались»
**Решение:** событие кассы партнёра уходит в Meta и GA4, если посетитель не отказался (флаг `tracking_declined`), как на Vino. Это заменяет часть спеки 63 про `consent.granted`.
**Причина:** так сейчас устроен баннер на Vino (коммит `96db4c8` в avamb/vinoandco-site). Отказ ничего не отправляет в рекламные кабинеты, обезличенная воронка считает шаг всё равно.
**Ключ канала:** хранится как SHA-256 в `settings.site.track_key_hash` (спека предлагала bcrypt: секрет случайный и длинный, быстрый хеш подходит).
