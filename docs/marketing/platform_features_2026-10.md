# Arena: полный перечень функций для маркетинга

Дата: 2026-11-04 (первая версия 2026-10-13). Назначение: планирование маркетинга. Файл собран из кода репозитория, спецификаций в `08_architecture/`, памяти проекта и разведки конкурентов (`docs/competitive/`).

Состояние продакшена на 04.11: бэкенд, ивент-центр, админка и страница билетов собраны из master `06817e0`, головная миграция 0196.

## Как читать статусы

- **Готово** — есть код, маршруты API и миграции, выкачено в продакшен. Можно описывать клиенту, но см. предупреждения в разделе 6.
- **Готово, выключено** — код в продакшене, но функция выключена флагом или не подключена ни у одного организатора.
- **На стенде** — работает на тестовом стенде, в продакшене нет.
- **Частично** — работает часть функции, остальное открыто.
- **В работе** — ведётся разработка.
- **Запланировано** — решение принято, кода нет.
- **Идея** — обсуждалось, решения нет.
- **Нет** — у конкурентов есть, у нас не будет или решения не принято (см. раздел 4).

Пометка «с 14.10», «с 03.11» и т. п. — дата выката в продакшен для функций, появившихся после первой версии файла.

Источники перечислены в разделе 8.

## 4. Осознанно не делаем

По источникам это решения владельца:

- Перепродажа без ограничения цены, динамическое ценообразование, потребительское приложение для поиска билетов, собственная почтовая служба, блокчейн и кешлес-браслеты, магазин в TikTok.
- Собственное приложение-сканер (вход остаётся в MACS), GetYourGuide, абонементы и подарочные карты — кроме случаев по запросу клиента. Мерч перестал быть исключением: магазин строится под первого клиента.
- Оплата через Meta Shops (checkout Meta).
- Stripe Smart Disputes: споры ведём своим потоком.
- Сторонняя продуктовая аналитика (PostHog и т. п.): своя система.

## 5. Открытые решения владельца

1. Добавить ли H1 (разметка Google) в волну SOC.
2. SOC-05: отправлять ли событие конверсии без хешированных данных, если покупатель не дал согласия (рекомендация: без хешей). Пилот: Учебный театр или Actorre.
3. Магазин: когда кэшбэк «Приведи друга» в магазине переходит на выплату после доставки.
4. Отписка в Brevo: даём ли покупателю снять блокировку без нового заказа; уходим ли с Brevo для транзакционных писем.
5. Импорт события: нужен ли «вставить текст».
6. Онбординг: срок хранения 180/365 дней; автоодобрение после 20 совпадений.
7. Сайт: количество городов и стран, логотипы доверия (Marina); тарифы после анализа конкурентов.
8. Платежи: провайдеры для Швейцарии и Балкан/Южной Америки не выбраны; правила идентификации организаторов по странам (нужна консультация юриста); подключение Stripe самим организатором.

## 6. Что нельзя утверждать в маркетинге сейчас

- **Flitt и AllPay** — не описывать как работающие у организаторов платформы: код в продакшене, но ни один организатор на них не подключён. AllPay работает только на сайтах WordPress через свой плагин.
- **Подключение Stripe «в два клика»** — нельзя: ключи вносит оператор, вебхук заводится вручную.
- **Возвраты** — автоматический возврат через провайдера обещать только для Stripe.
- **Споры** — автоматическую подготовку ответа обещать только для Stripe; ответ отправляет организатор нажатием, без этого ничего не уходит. Выигрыш спора не гарантирован.
- **Магазин** — только на стенде; продакшена нет до переноса домена первого клиента.
- **Биллинг, кредиты и white label** — в продакшене выключены для организаторов, плата за бренд не начисляется.
- **Брошенная корзина** — только виджет и страница события, не сайты WordPress.
- **«Приведи друга»** — кэшбэк приходит после мероприятия друга и только если на балансе Stripe организатора хватает денег; живьём в продакшене не проверено.
- **Бот, выплаты** — организатор не видит выплаты и баланс в боте.
- **Плагин WordPress** — версия 0.1.0, в каталоге WordPress не опубликован.
- **Языки** — страницы продажи на пяти языках (без немецкого и французского), бот на трёх; немецкий и французский есть только в письмах и билетах.
- **Сбор покупателя** — в Испании процентный сбор покупателя запрещён; на испанских событиях не обещать его без юридической проверки.
- **Письма могут не дойти** — если покупатель раньше нажал «Отписаться» в письме, Brevo не доставит ему билеты; предупреждение пока не сделано.
- **Документация** — `08_architecture/14_current_implementation_overview_ru.md` датирован 18.07 и устарел (миграции до 0069, сейчас головная 0196). Опираться на код и этот файл.
- **Не проверено живыми людьми на продакшене** — покупка по реферальной ссылке и отложенный кэшбэк, оформление текста нейросетью в боте, печать PDF-вкладыша QR.

### 7.6. Что предложить театру, который уже на Wix

- **Цену за билет не выигрывать.** При ценах 15–25 € сбор Wix (0,38–0,63 €) ниже нашего варианта «Старт» (0,75 €) на 13.10. Перед разговором сверить с тарифами, принятыми 16.10 (`billing-pricing-decisions`).
- **Выигрывать на том, что Wix не покрывает:** продажи, возвраты и пригласительные через Telegram, перенос сеанса с письмом покупателю, PDF на языке покупателя, включая иврит, QR на афише с атрибуцией.
- **Переезд без простоя:** импорт событий со своей страницы, схемы и покупателей, как у Bil24.
- **Сайт остаётся на Wix на самом дешёвом платном тарифе Light** (14 € в месяц при годовой оплате, без IVA). Тариф Light не принимает оплату через Wix, но Арене это не нужно: деньги идут организатору через его Stripe.
- **Виджет встраивается через пользовательский код сайта.** По справке Wix для пользовательских элементов нужен премиум-план, подключённый домен и отсутствие рекламы Wix; Light подходит. Вариант через iframe не годится: после оплаты покупатель вернётся на страницу Арены, а не на сайт театра. Проверить в живом кабинете Wix до предложения.
- **Техническое условие на нашей стороне:** домен сайта театра нужно добавить в CORS_ALLOWED_ORIGINS на сервере. Это изменение конфигурации, решение за владельцем.
- **Сказать честно про ограничения Wix:** одна схема на мероприятие, сверка места при сканировании не подтверждена. Проверить до разговора с театром.
