# Рабочий порядок: Андрей и Марина (GitHub)

Правило: **перед работой забрать свежее, работать в своей ветке, после работы отправить на GitHub.**
Память Claude у каждого своя и между компьютерами не синхронизируется. Всё, что нужно знать обоим, пишется в репозиторий (см. «Общие знания»).

## В начале работы
1. `git checkout master` и `git pull` (или сказать Claude: «Сначала обнови проект с GitHub»).
2. Прочитать `docs/decisions.md` и `docs/known-issues.md`, если они менялись (`git log -5 -- docs/decisions.md docs/known-issues.md`).
3. Создать ветку под задачу: `git checkout -b <имя>/<что-делаем>` (например `marina/crm-filters`).

## Во время работы
- Работать только в своей ветке. В `master` и `main` напрямую не пушить, только через Pull Request.
- Репозитории сайтов (`arena-site` и др.): push в основную ветку запускает деплой на боевой сайт.
- Секреты (`.env`, `.local/`, токены, ключи) не коммитить и не отправлять в чаты.
- Решение или ловушку, важные обоим, сразу записать в `docs/decisions.md` или `docs/known-issues.md`.

## В конце работы
1. Закоммитить: `git add <файлы>` и `git commit -m "что сделано"`. Не `git add -A` вслепую: сначала `git status`, секреты и чужие файлы не добавлять.
2. Отправить ветку: `git push -u origin <ветка>`. Если работа не готова, всё равно отправить, чтобы ничего не потерялось.
3. Если готово, открыть Pull Request в `master` (или сказать Claude: «Закоммить, отправь ветку и создай Pull Request») и написать Андрею.
4. Добавить строку в `docs/progress.md`, если задача заметная.

Фразы для Claude: в начале «Сначала обнови проект с GitHub и создай новую ветку для задачи», в конце «Закоммить изменения, отправь ветку на GitHub и создай Pull Request».

## Общие знания (вместо личной памяти)
| Файл | Что писать |
|---|---|
| `docs/decisions.md` | Принятое решение: дата, суть, причина. |
| `docs/known-issues.md` | Ловушка или баг, о который можно споткнуться: симптом, причина, обход. |
| `docs/progress.md` | Одна строка о сделанном: дата, кто, что. |

Личная память Claude остаётся личной (предпочтения, контекст сессий). Если запись нужна второму человеку, её место в этих файлах.
