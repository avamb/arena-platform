## Детали по пунктам

### 1. Единая админка — ✅
- Один React SPA (apps/admin-web), 18 маршрутов: события/сеансы, площадки,
  заказы, билеты, возвраты, каналы продаж, платежи, гео-реестр, аудит и т.д.
- `legacyModules.ts` прямо фиксирует: заменяем четыре legacy-приложения Bil24
  одним. POS («касса») задуман как workspace внутри того же приложения — сейчас
  placeholder, роли «кассир» нет.
- Навигация по правам (RBAC, ~115 permission-кодов), а не по ролям.

### 2. Любое устройство — 🟡
- Чистый веб: nginx + SPA + Go API, никакой привязки к устройству/софту.
- Мобильное: брейкпоинт 768px, два шелла (desktop sidebar / mobile drawer),
  ResponsiveTable → карточки, 44px тач-таргеты. Конвертированы списки orders,
  tickets, refunds, channels, payments, organizations, venues, events.
- Не конвертировано: под-таблицы внутри карточки события (сеансы, тиры,
  публикации — raw `<table>`), волна M-2…M-8 (шелл, формы, скриншот-гейт CI)
  и AB-6 (аудит всех маршрутов на 375×812) — в бэклоге.

### 3. Несколько картинок — ✅ (свежедоставлено)
- AB-47 (постер на сеанс), AB-47b (галерея: ≤5 постеров + ≤20 элементов,
  видеоссылки youtube/vk/rutube/vimeo, порядок, атомарный PUT), AB-47c
  (обложка + галерея в публичном фиде и WP-контракте) — все в master.
- Пробел: в самом виджете покупки галерея не отображается (только обложка);
  данные в фиде уже есть — нужна карусель на стороне виджета/сайта.

### 4. Отчёты о прошедших событиях — ❌
- `event_reports` в БД — это финансовый отчёт (продажи/возвраты/сканы),
  не медиа-отчёт. `/reports` в админке — заглушка.
- Требуется новая фича: пост-ивент контент (фото/видео/текст) + отображение
  на публичной странице события в состоянии «прошедшее».
- Быстрый обходной путь: галерея сеанса уже позволяет догрузить фото и видео
  после события — не хватает публичного вывода «архива».

### 5. Поиск покупок — 🔴 (самый чувствительный пробел для п.5 письма)
- `GET /v1/admin/orders`: только limit/offset/org_id/state. Ни e-mail, ни
  номера заказа, ни события, ни дат. E-mail покупателя хранится в
  `tickets.holder_email` — запросов по нему нет.
- Нет org-scoped списка заказов → организатор в принципе не имеет экрана
  «мои заказы»; консоль видна только суперадмину (с X-Admin-Reason).
- Нет человекочитаемых номеров заказов (AB-22 pending; display_numbers есть
  для орг/площадок/событий, но не для заказов/билетов).
- Нужно: org-scoped orders API + поиск по e-mail/номеру + полная карточка
  заказа (билеты, возвраты, платёж, позиции — сейчас «backend gap» тайлы).

### 6. Города и площадки — 🟡
- Есть: CRUD площадок, создание города из формы площадки с геокодингом
  (AB-35 ✅), гео-реестр стран/городов (bilingual en/ru), планы залов
  (SVG/JSON, версии, fork) — self-service для организатора.
- Пробел прав: `organizer` — только venue.read; запись у admin/org_admin/
  superadmin, при этом org_admin нельзя выдать через memberships (только
  через глобальные роли). Города — только `geo.admin`.
- Для Vino&Co: либо расширить права роли, либо завести им org_admin-доступ.
  AB-20 (геокодинг-first создание площадки) и AB-21 (импорт городов/площадок
  из Bil24) — в бэклоге.

### 7. Возвраты — 🔴
- Бэкенд готов наполовину: POST /v1/refunds (частичная сумма валидируется
  против остатка intent'а), approve/reject, идемпотентный webhook
  (Stripe/AllPay подписи), отмена билетов при succeeded.
- Не готово: (а) UI — страница Refunds read-only, ни одной кнопки;
  (б) реальный вызов RefundPayment у провайдера не подключён — движение денег
  сейчас возможно только «вручную в кабинете провайдера + webhook назад»;
  (в) AB-49 (отмена билета с режимами none/manual/automatic, частичные
  возвраты из UI) и AB-50 (события ticket.refunded для сканера) — не начаты.

### 8. Письмо после покупки per-event — ❌
- Сейчас: 2 типа писем (ticket, invitation) × 4 локали, вшиты компилятором.
  Персонализация — только брендинг организации (лого, реквизиты) и, по плану
  AB-9/AB-10 (pending), From/Reply-To организатора.
- Нужно: хранение шаблонов/фрагментов в БД (per-org → per-event override),
  редактор в админке (маршрут /content — сейчас заглушка), безопасный
  рендеринг. Фичи в бэклоге нет — надо заводить.

### 9. Письмо-фидбек после события — ❌
- Фичи нет. Инфраструктура отложенных заданий готова: worker_jobs с
  scheduled_at + индекс (status, scheduled_at), идемпотентность, retry,
  dead-letter. Реализация = новый job-тип + триггер по окончании сеанса +
  шаблон (упирается в тот же пробел п.8, если текст должен быть per-event).

### 10. Картинка на языке мероприятия — ❌
- Локализуемы только тексты события (i18n_text: event.name/description через
  `translations` map в API) и гео-реестр. Виджет уже умеет en/ru/cs/he + RTL.
- У media_objects и session_media_items нет колонки locale — картинка одна
  на всех языках. Нужно: locale-измерение у медиа (постер per-locale с
  fallback на дефолт) + резолвинг в фиде по ?lang.

## Что это значит для подключения Vino&Co

Уже закрыто платформой: единая веб-админка (1), доступ с любого устройства (2,
с оговоркой про мобильную полировку), мультикартинки (3), self-service площадки
и залы (6, при выдаче нужных прав).

Обязательные доработки до полноценной замены Bil24 для Vino&Co (по приоритету):
1. **Поиск/карточка заказов + org-доступ** (п.5) — новая фича, бэклога нет.
2. **UI возвратов + подключение RefundPayment провайдера** (п.7) — AB-49/AB-50
   уже расписаны в бэклоге, плюс провайдерская интеграция.
3. **Мобильная волна M-2…M-8 / AB-6** (п.2 и «как Shopify с телефона»).
4. **Per-event кастомизация письма** (п.8) — новая фича (расширить /content).
5. **Пост-ивент фидбек-письмо** (п.9) — новая фича, инфраструктура готова.
6. **Пост-ивент фото/видеоотчёт** (п.4) — новая фича; частично закрывается
   существующей галереей + публичным «архивным» выводом.
7. **Per-locale постеры** (п.10) — новая фича в медиа-слое.
8. Галерея в виджете (карусель) — данные уже в фиде, только фронт.

Отдельно про миграцию с Bil24: arena-bil24-import умеет события (CSV/JSON)
и живой импорт стран/городов/площадок по Bil24 API; заказы, покупатели,
схемы залов и медиа-файлы НЕ мигрируются — для Vino&Co надо решить, нужна ли
история продаж.

Предлагаемое место для новых фич: блок AB-52+ в
09_autoforge/admin_bootstrap_backlog.md (текущий хвост — AB-51).
