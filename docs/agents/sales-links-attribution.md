# Sales links, QR and attribution

Tracked sales links, QR routes, printable insert, attribution on the widget and tickets page. Verbatim items of the former single AGENTS.md. Add a new trap here as a `- **Title.** ...` item and put one title line for it into the index in AGENTS.md.

- **Sales links and QR (spec 43, migration 0167, run QL stage 1, 2026-10-24).** `sales_links` / `sales_link_hits`, `checkout_sessions.attribution`, `orders.sales_link_id` + `orders.attribution`; permissions `sales_link.read` / `sales_link.manage` (org_admin, organizer, platform_superadmin; NOT in `apikeys.IsForbiddenScope`). The public redirect `GET|HEAD /go/{code}` (`httpserver/hgo`, mounted from `mountOperationalRoutes`) is host-independent, answers 302 for everything a person could print (unknown code, archived link, missing organization, RATE LIMIT — all go to `SHORT_LINK_FALLBACK_URL`, then `PUBLIC_TICKETS_BASE_URL`, then `APP_PUBLIC_URL`; only a database error is 503), counts a scan AFTER the response was flushed, in one CTE `CountSalesLinkScan`, behind a 4-slot non-blocking semaphore (`dropped` outcome) and an in-memory dedup keyed by sha256 of code|client /64|UA|UTC day|per-process salt (`salelinks.Dedup`); the request log omits `remote_addr`/`user_agent` for it; `CF-IPCountry` is trusted only when `TRUSTED_PROXY_COUNT > 0`, so the origin must be locked to Cloudflare. Traps: (1) the openapi drift test walks EVERY chi route and method, root routes and HEAD included, byte for byte — a catch-all `/go/{code}/*` must be documented under that literal path, and `TestErrorResponses_AllErrorsUseErrorEnvelopeRef` exempts only `/healthz`, `/readyz`, `/metrics`, so 4xx/5xx bodies of a root route are the JSON envelope; (2) the only place that formats a short link is `salelinks.ShortURL` — `tests/staticanalysis/short_link_url_test.go` fails on a `/go/` or `go.arenasoldout.com` literal outside `salelinks`/`config`/the chi patterns of `mount_go.go` (`// allow:shortlink` with a reason otherwise); (3) `attribution.Clean` is the ONE cleaner for the §3 JSON (a `landed_at` outside the 7-day window or in the future drops the whole touch; a present-but-not-string `landed_at` too; an absent one means now); `ref` becomes `orders.sales_link_id` only for a link of the SAME organization (`attribution.ResolveLink`, called on the pool BEFORE `BeginTx` on both `checkout/start` and CREATE_ORDER_EXT); a re-sent gateway cart merges touches on the ORDER (`MergeTouch`, earlier touch → `first`) and copies the result back to the new `checkout_sessions` row; (4) `BuildDestination` keeps the target's own query pairs verbatim (no `url.Values` round trip: it drops `;` pairs and re-sorts); (5) a test code must use the alphabet `abcdefghjkmnpqrstuvwxyz23456789` — `i`, `l`, `o`, `0`, `1` make `NormalizeCode` refuse it and the request silently falls back; (6) `PublicAPIIPRateLimit: 0` disables the IP bucket in test servers, a flood test sets it through the `mutate` hook; (7) a fixture that deletes an organization, event or session deletes `sales_link_hits`, then `sales_links` AFTER `orders` (`orders.sales_link_id` FK, no cascade); (8) widening `OrderRow` touches `superadmin.sql(.go)` `ListAllOrders`, `orders_search.sql.go` `SearchOrdersByOrg` (hand scans) and the fake rows in `hcustomers`/`horders` handler tests. Session summary `sources` lives on the SESSION summary only (`horders/session_sources.go`), never in `summaryCore` (the event batch is compared with DeepEqual). Runbook: `docs/ops/sales_links_ru.md`. **Bot (QL-8, `eventbot/sales_link_dialog.go`, kind `sales_link`, presses `ql:*`, keys `bot.ql.*`):** state is one `bot_dialogs` row saved before every reply. Links are named by UUID on the card (`ql:v|st|qr|ar|ua|rt:<id>`, work after the dialog ran out), choices (events, dates) by page index. A retarget is confirmed with ONE press (`ql:rt:ok:<id>`, valid only at step `retarget_confirm` for that link), no typed word. The code goes out as a PHOTO (`sendPhoto`, PNG 1024) plus a DOCUMENT (`<code>.svg`); the e2e stub records `[photo name]` / `[document name]` lines. The date card's button keeps its `ql:` prefix through `sesKeyboard` (the press ends the Sessions dialog). The bot never builds a short address: it prints `short_url` from the API. Stats days are the API's UTC days (said in the text). **List (QL-9, `eventbot/sales_link_list.go`):** the main menu's `ql:menu` opens the list (filters reset), `ql:list` returns to it as the person left it, `ql:new` starts a link (from the narrowed event when one is set), `ql:le:<event>` narrows to one event (the link card's "to this event's list"). The state (`lf` filter, `le` event, `lp` page, `lc` cursor stack, `ln` next cursor, `li` row ids, `pi` event-picker ids) lives in its OWN `bot_dialogs` row, kind `sales_link_list` (steps `list` / `list_events`), apart from the creation dialog `sales_link`: a press on a link card ends the creation dialog (so a text typed next is not a label) and must not take the list with it. Both kinds own the `ql` prefix in `dialogOwners`, the list takes no text (`salesLinkListText` returns false). The API pages only forward by keyset cursor, so `lc[k]` is the cursor that fetches page k+1 and a "back" press refetches with the stored one (no total, so the pager shows "‹ 2 ›" without a page count). A page that empties after an archive falls back to page 1. A row press (`ql:o:<i>`) is honoured only at step `list`, a page number other than current±1 redraws the current page.

- **Attribution on the clients (spec 43 stages 2-3, 2026-10-24).** The widget keeps the buyer's touch in `apps/widget/src/lib/attribution.ts`: `localStorage` key `arena_attr:<feedToken>` (scope = the sales channel, not the event), 7-day `expires_at`, every storage call in try/catch; a touch is an address with `ref`, `utm_source` or `utm_campaign` (one `utm_medium` alone is not a touch and never overwrites a stored one), values checked with the server alphabet `[A-Za-z0-9._~-]{1,64}`, `ref` lower-cased; a new touch that differs in `ref`, `utm_source` OR `utm_campaign` moves the stored one into `first` (the same three fields `attribution.MergeTouch` compares), and an existing `first` stays the very first touch. The object goes ONLY into `checkout/start` (never `recover` or `quote`); `ArenaTickets.test.ts` pins that by source scan. Server side the 7-day window applies to the LAST touch only: `attribution.Clean` keeps a `first` of any age as long as its `landed_at` is RFC 3339, not in the future and not later than the last touch (decision R-QL23) - do not put the window back on `first`, a 10-day-old first touch is the normal case. `?session=<uuid>` on the hosted event page preselects the date (`render.ts` `preselectedSession` -> `session-id`); `pickInitialSession` (`lib/store.ts`) skips a cancelled session. The bot's link screens live in TWO dialog kinds: `sales_link` (creation, retarget question; deleted when the card is shown and on every card button, so a later text is never taken for a label) and `sales_link_list` (filter, event, cursor stack, rows on screen; takes no text), both owning the `ql:` prefix. A reviewer agent must never `git checkout` in the orchestrator's checkout.

- **A sales link's card says where the code leads and WHY, from the server's `destination_reason` (QL-8b, the owner's first live run, 2026-10-24).** `salelinks.ResolveDetailed` / `ResolveFull` give the destination, the degraded flag and a reason code naming what decided the FINAL page (`event_not_published`, `event_no_slug`, `session_not_live`, `promoter_unavailable`, `archived`, `no_page_address` — the redirect goes to the platform's fallback page —, `org_not_found`; empty = the target itself); `Resolve`/`ResolveWithFacts` are the two-value wrappers over the same chain, so a new rung of the chain sets its reason there and nowhere else, and `hsalelinks.present` only copies it. The bot (`eventbot.slWhyKey`) maps a code to a `bot.ql.card_why_*` text and advises «Перенацелить» ONLY where another target changes the address (a cancelled date, an archived promoter); an unpublished event says "publish it", a missing page address says "write to support" — never again "press Redirect and choose another target" for a code a retarget cannot mend. The card always prints `bot.ql.card_dest` («Сейчас ведёт на: <destination_url>») or `card_no_dest` (the platform's fallback page). A retarget to the SAME target (`slSameTarget`, kind plus the one id or address) is answered `bot.ql.rt_same` from the confirm step without a PATCH and without an audit row; after a real move `rt_done` ("a new page") only when `destination_url` appeared or changed against the `PrevDest` stored at the retarget's start, else `rt_done_same_dest` / `rt_done_no_dest`. A new reason code needs: the constant in `salelinks`, a case in `slWhyKey`, a `bot.ql.card_why_*` key in `ql_keys.go` and all three catalogs, and the openapi description of `destination_reason`. E2E: `bot_e2e_sales_links_card_integration_test.go` (one server with `PUBLIC_TICKETS_BASE_URL`, one without; the event page there is `/<org slug>/<event slug>`, the organization's slug leads when the event has no promoter).

- **The printable insert of a sales link is `format=pdf` of the QR route (QL-13, spec 43 §6.5), rendered by `internal/platform/salelinks/pdfinsert`.** `GET …/sales-links/{id}/qr?format=pdf&paper=a6|a5` (a6 default, file `<code>-<paper>.pdf`) draws the logo (or the organization name) on top, the name of what the code sells (event; event + session start on the venue clock through `pdfinsert.SessionLine`; promoter; organization), the QR as filled black rectangles with a four-module quiet zone (never a raster image), the line `salelinks.insert.scan_and_buy` from the shared i18n bundle (en/ru/es/cs/he, English without a bundle) and the short address without its scheme. Fonts come from `pdf.DejaVuFonts()` (`delivery/pdf/fonts.go` exports the embedded bytes; never copy the TTFs), determinism as on the ticket (compression off, catalog sort, pinned dates), so the ETag is the body hash. Hebrew is drawn in visual order per line by `visualLine` (Latin/digit runs keep their order, brackets mirror): glyph order only, no shaping, like the ticket; a test expecting Hebrew text must expect the REVERSED line, the address is never reordered. `hsalelinks.Handler.WithInsert(bundle, logos)` takes `s.bundle` (the gateway bundle: integration test servers pass none, so the line is English there) and `mediaresolver.New(s.media, …)`; a logo that fails to load within 5 s only logs. Names come from `gen.GetSalesLinkInsertFacts` (own files `sales_link_insert_facts.sql(.go)`). The bot sends the A6 PDF as the third document after the PNG photo and the SVG (`bot.ql.pdf_caption`). Text runs are read back in tests with the `pdfDrawnText` approach (a local copy per package). Python patch scripts for Go files with backticks must be written to the scratchpad with the Write tool: the Bash tool refuses a heredoc holding a backtick.
