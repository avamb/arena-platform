Файл: `arena-ux/<YYYY-MM-DD>-clean/report.md`, снимки рядом в `screens/`. Язык отчёта: русский.
Рядом обязателен протокол результата `results.md` (раздел «Протокол результата» ниже).
Цитаты интерфейса: дословно, в кавычках, на языке оригинала.

## Протокол результата (обязателен для каждого прогона)

Отдельный файл `results.md` в папке прогона, рядом с `report.md`. Формат задан тест-планом платформы: `docs/testing/full_functional_test_plan_2026-11-01.md`, раздел B.1. Без этого файла прогон не засчитывается как приёмка, каким бы подробным ни был `report.md`.

```markdown
# Протокол прогона <тип> <дата>, Hermes

## Манифест версий (записать ДО первого шага и сверить ПОСЛЕ последнего)
| Компонент | Как узнал | Значение |
|---|---|---|
| arena-api | GET https://api.arenasoldout.com/v1/info → commit | |
| arena-worker | у Андрея: строка лога при старте с commit= или стартовое сообщение watchdog | |
| arena-bot | у Андрея: строка лога при старте с commit= | |
| Event Center | имя главного бандла index-*.js на events.arenasoldout.com | |
| tickets-page / виджет | ETag или хэш /widget/v1/arena-tickets.js | |
| shop-page (если в прогоне) | имя главного бандла | |
| Навык Hermes | version из SKILL.md | |
| Окружение и организация | прод / стенд; ABH TEAM / UX Hermes <дата> | |

Если значение изменилось между началом и концом (выкатили новую версию посреди прогона), шаги, сделанные до смены и касающиеся этого компонента, получают NOT RUN и повторяются.

## Результаты
| Шаг (F4, N8.2, Z7…) | Кейс плана (NEW-11, PAY-11…) | Статус | Время (Мадрид) | Evidence | Находка | Комментарий |
|---|---|---|---|---|---|---|

## Итог
PASS: _ · FAIL: _ · BLOCKED: _ · SKIP: _ · NOT RUN: _.
Обязательные шаги не в PASS: <список с причиной>.
Вывод: приёмка пройдена / не пройдена.
```

Статусы:
- **PASS** — получено ожидаемое, evidence приложено (снимок, номер заказа, письмо);
- **FAIL** — не совпало, приложены evidence и шаги воспроизведения;
- **BLOCKED** — выполнить нельзя: дефект раньше по пути, нет доступа, нет кода от Андрея;
- **SKIP** — не выполнялся по слову Андрея (записать, когда он это сказал);
- **NOT RUN** — не дошёл, или версия компонента сменилась.

PASS и FAIL без evidence не считаются. Любой обязательный шаг прогона не в PASS означает «приёмка не пройдена», даже если остальной отчёт хороший. SKIP допустим только со словом Андрея. Номер карты и ключи в evidence не пишутся.

Соответствие шагов кейсам плана: для `zero-to-paid.md` — таблица в конце файла. Для `functional-run.md` и `clean-run.md` ставь ближайший кейс плана или «—», если такого кейса нет.

## Правила хорошей рекомендации

- Конкретно: не «улучшить текст», а «заменить "Квота" на "Сколько мест в этой категории"».
- Одна находка = одна проблема. Если на экране три проблемы, это три строки.
- Предлагай самое дешёвое исправление первым (текст, подсказка, порядок), переделку экрана вторым.
- Не выдумывай: если не уверен, что это ошибка, пометь `?` и объясни, что проверить.
- Не повторяй одну и ту же находку на каждом экране: одна строка + «встречается также: …».

## Сводка Андрею в чат (после отчёта)

5–10 строк: сколько находок по уровням (S1/S2/S3/S4) и сколько багов, время от сайта до первого билета, топ-5 одной строкой каждая, что не
проверено, где лежит файл отчёта, какие тестовые данные остались в системе.
