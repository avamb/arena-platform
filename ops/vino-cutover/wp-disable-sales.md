# Как остановить НОВЫЕ продажи на WordPress Vino&Co (T0 − 30 мин) и вернуть их

Спека 62 §14.2 п. 2: на WP отключается начало новых продаж, сам WP не останавливается — AllPay IPN, вебхуки
Brevo, возврат старых платежей, WP-Cron и PAY_ORDER для уже созданных заказов продолжают работать.

Контейнер WP на хосте `lead-parser` находится так (дальше везде `$WP`):

```
WP=$(docker ps --format '{{.Names}}' | grep -E '^asoconnector-vinoandcotempvino-.*-wordpress-1$')
```

 Префикс таблиц
`x4gd_`. wp-cli в контейнере **нет**; опция меняется тем же способом, что в `cutover-settings.php`:
`php -r` с `wp-load.php` внутри контейнера (то есть тот же PHP, тот же Redis-объектный кэш, что у сайта, поэтому
значение сразу видно сайту).

## Выбранный переключатель: опция `vino_maintenance`

Заглушка обслуживания, mu-plugin `vino-maintenance.php` (уже стоит на проде, писался именно для «окон
деплоя»). Пока `vino_maintenance = 1`:

- анонимный посетитель любой страницы сайта получает **503 + `Retry-After: 1800`** с текстом «Мы обновляем сайт…»
  на трёх языках, `noindex`; кнопка покупки и модалка недоступны, потому что недоступна сама страница;
- **продолжают работать**: вошедшие пользователи, `/wp-admin/`, `wp-login.php`, WP-Cron, admin-ajax и REST,
  все вебхуки (`?wc-api=…` AllPay, `/wp-json/lops/` Brevo), поэтому уже начатая оплата доходит до конца и
  ничего «в полёте» не теряется.

Включить:

```
ssh lead-parser
docker exec $WP php -r 'require "/var/www/html/wp-load.php"; update_option("vino_maintenance", 1, false); echo "vino_maintenance=", get_option("vino_maintenance"), "\n";'
```

Свой текст вместо стандартного (необязательно, HTML допустим только базовый, `wp_kses_post`):

```
docker exec $WP php -r 'require "/var/www/html/wp-load.php"; update_option("vino_maintenance_text", "Переезжаем на новый сайт. Загляните через полчаса.", false);'
```

**Сразу после включения сбросить кеш Cloudflare** (иначе краевой кеш продолжит отдавать старые страницы с
рабочей кнопкой: у прода заголовок `cf-edge-cache: cache,platform=wordpress`, то есть HTML кешируется на краю).
Сброс делает владелец в панели Cloudflare (Caching → Purge Everything) либо командой из контейнера сборщика
сайта, токен при этом нигде не печатается (см. runbook, шаг 4).

Проверка (с любого компьютера, не из-под входа в WP):

```
curl -s -o /dev/null -D - https://vinoandco.events/ | head -n 12      # ждём HTTP/1.1 503 и retry-after: 1800
curl -s -o /dev/null -w '%{http_code}\n' 'https://vinoandco.events/wp-login.php'   # 200, вход оператора работает
```

Ожидаемое побочное действие, о нём надо знать до начала: для анонимного посетителя заглушка стоит и на
`/?vino_pay_back=…` (возврат со страницы AllPay без оплаты) и на `/payment-successful/order-received/…`
(страница «Спасибо»). За эти ≤ 30 минут вернувшийся покупатель увидит заглушку; заказ не теряется: оплаченный
получит билеты письмом, неоплаченный отменит и освободит места задача `vino_apw_deadline` по концу окна оплаты.
Поэтому окно между «включили» и «переключили маршрут» держим коротким, а в инвентаризации (`wp-inventory.php`)
после T0 смотрим заказы `pending`.

## Откат (вернуть продажи на WP)

```
docker exec $WP php -r 'require "/var/www/html/wp-load.php"; delete_option("vino_maintenance"); delete_option("vino_maintenance_text"); var_dump(get_option("vino_maintenance", "unset"));'
```

Должно напечатать `string(5) "unset"`. Затем снова сбросить кеш Cloudflare и проверить
`curl -sI https://vinoandco.events/` (ждём 200 и `x-powered-by: PHP`). Состояние до включения: опция
`vino_maintenance` на проде **не задана** (проверено 07.11.2026), поэтому откат = удаление опции, а не
возврат прежнего значения.

## Почему не другие переключатели

| Вариант | Почему нет |
|---|---|
| Состояние продаж на карточках (`_bil24_sales_state` = `soon`/`soldout`) | Каталожный синк (каждые 15 мин) читает это поле как «ручное состояние сайта»: если оно помечено источником `arena`, следующий синк его **снимет**, а если нет, **отправит в Arena** (`bil24_sales_state_push`) и закроет событие на платформе, то есть закроет продажи и на новом сайте. Опасно, не трогать. |
| Выключить шлюз AllPay в WooCommerce | Это правка платёжной настройки, а не «начала продаж»; заказы в полёте и повторы возврата идут через тот же шлюз. |
| Снять публикацию событий в канале WP | Склад общий с новым каналом; это решение платформы, не WP, и оно обратимо хуже. |
| Остановить контейнер WP | Нельзя: IPN, вебхуки, Cron, возвраты (спека §14.2 п. 2). |

Если заглушка в полчаса окажется слишком грубой при репетиции, мягче можно только кодом (новый
mu-plugin с фильтром на `bil24_sales_closed`), а это правка WP-кода с выкаткой, которой по плану
переключения лучше не делать.
