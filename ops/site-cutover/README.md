# Переключение сайта с WordPress на сайт поверх feed платформы

Общие инструменты переключения публичных страниц на статический сайт. Один каталог — один сайт: параметры в `sites/<сайт>.json`, пробы маршрута в `probes/<сайт>.probes`. Первым переключением был vinoandco.events; его скрипты остаются в `ops/vino-cutover/` и работают как раньше.

Состав:

| Файл | Что делает |
|---|---|
| `sites/<сайт>.json` | Все параметры сайта: домен, резолвер сертификата, какие пути отдаёт новый сайт, какие остаются за WordPress, правило куки оператора. Адреса контейнеров здесь не хранятся. |
| `render.mjs` | Рендер файла маршрута Traefik (`<имя>-site.yml`, T0) и файла отката (`<имя>-rollback.yml`, до T2). Без `--out` печатает файл T0 в stdout. |
| `render.test.mjs` | Тесты рендера: `node --test ops/site-cutover/render.test.mjs`. |
| `probes/<сайт>.probes` | Пробы маршрута: одна строка на запрос, `SITE` или `WP`, путь и аргументы curl. Только GET и HEAD. |
| `routing-check.sh` | Прогон проб: `<файл проб> <домен> <ip> <порт> [аргументы curl]`. Тело или другой метод не отправляется: такая проба отклоняется. `DRY=1` печатает план без запросов. |

## Порядок

1. Рендер в каталог, которого нет в репозитории:

   ```powershell
   node ops/site-cutover/render.mjs ops/site-cutover/sites/lampyris.json --site-url http://<контейнер сайта>:80 --wp-url http://<контейнер WordPress>:80 --out $env:TEMP\lampyris-route
   ```

   Адреса контейнеров читает владелец через `docker ps` на сервере. Без `--site-url` и `--wp-url` рендер T0 не выполняется: это защита от пустого адреса в проде.

2. Проверка на стейдже или на фейковом хосте (`--resolve`, без DNS и сертификата): `routing-check.sh ops/site-cutover/probes/lampyris.probes <фейковый домен> <ip> 443 -k`.
3. T0: `<имя>-site.yml` кладётся в `/etc/dokploy/traefik/dynamic/`. Traefik перечитывает файл сам.
4. Откат до T2: вместо него кладётся `<имя>-rollback.yml` под тем же именем. Удалять файл целиком — откат репетиции, не продакшена.

Порядок приоритетов в файле маршрута: 3000 — пути нового сайта, которые он отдаёт всегда (в том числе при откате); 2000 — пути, которые остаются за WordPress; 1500 — ассеты и REST оператора только с кукой входа WordPress; 1000 — всё остальное на домене.

## Правила

- Вебхуки и оплаты проверяются только GET или HEAD (`-I`). Живой POST ни одной пробой не отправляется (урок У-19 спеки 63).
- Файлы маршрута не коммитятся с адресами контейнеров. В репозитории только конфиг без адресов.
- Ключи, токены и id Dokploy сюда не кладутся.
- Новый сайт: добавить `sites/<сайт>.json` и `probes/<сайт>.probes`, потом тесты рендера.
